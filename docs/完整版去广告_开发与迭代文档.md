# 完整版·去广告（full_concat）开发与迭代文档

> 第三个生产模式，与「AI配音解说」「视频重组」并列。
> 把用户选的多段录制素材，按时间戳排序、自动去掉广告/其他栏目/片头片尾/赞助预告，拼成某个**目标栏目**的一条干净完整版。
> 本文记录：原始需求 → 需求演进 → 实现架构 → 历次迭代解决的问题与方法 → 关键设计取舍 → 配置 → 运维注意。

---

## 一、需求

### 1.1 原始需求
- 对用户选择的多段远程素材，组合成一个「完整版」。
- 素材名带时间戳（`YYYYMMDD_HHMMSS`），按时间戳排序。
- 过滤掉广告。

### 1.2 演进后的完整需求（按栏目拉片）
选中的素材是某**一个栏目**（如《凤凰聚焦》）的一段连续「拉片」，目标是产出这条栏目的干净完整版：

1. **目标栏目**由画面里的「栏目角标」决定（凤凰每个栏目画面右下角带栏目名）。时间戳也和排期表一致，可做兜底。
2. **保留**：属于目标栏目的全部正片内容，**包括它自己的片头/片尾**（哪怕中间再次出现片头）。
3. **删除**：其他栏目的内容、其他栏目的预告/播报、广告、台标/垫片、赞助/冠名卡。
4. **不精编、不删减正片**：只去杂质，不做高光精选；正片一句不少，时长基本就是整集时长。
5. **节目中间插播的广告/片头要删**，但节目自己的片头要留。
6. **重点人物提示**：内容涉及 习近平/李强/赵乐际/王沪宁/蔡奇/丁薛祥/李希 时，在「移除广告报告」旁显示 🔥，否则 🍀。人名支持**Web 端在线配置**，文件里只是打底名单。

## 二、整体架构与数据流

新增 `production_mode = "full_concat"`，模式从前端 `productionMode` → `RunRequest.production_mode` → 任务 manifest → `step_order(mode, unified)` 透传。

```
选多段素材(本地/远程)
  → source_prepare（下载 + 写 source_manifest）
  → source_analysis / source_aggregate   ← 复用现成公共分析（ASR + 画面 + timeline_digest）
  → ad_detection            ← 逐段判定 目标栏目/其他栏目/广告/赞助/预告/包装；产出 ad_detection.json
  → full_concat_plan        ← 按时间戳排序、保留目标栏目段、合并成 clip；产出 full_concat_cut_plan.json
  → full_concat_render      ← 复用 reassembly 的裁切+ffmpeg concat；产出成片 + 移除报告
```

- 渲染复用 `_render_reassembly_one()`，cut plan 的 schema 对齐 `reassembly_cut_plan`。
- 产物目录：`edit/ad_detection/`、`edit/full_concat_cut_plan/`、`edit/full_concat_drafts/`。
- 模式为原声：`audio_policy=original`、`skip_tts`、不配音。

### 关键信号来源
逐段判定的输入是聚合后的 `timeline_digest`（全覆盖、source-aware），每段含：
`speech`（ASR）、`screen_text`（画面文字）、`column_bug`（**栏目角标**）、`scene`/`footage_types`（镜头类型，含"片头包装"）、本地时间码、`source_id`。

## 三、核心模块：newsclip_agent/ad_detection.py

纯函数 + 步骤共用，可离线单测（`tests/test_ad_detection.py`）。

- `resolve_target_column(...)`：目标栏目 = **角标多数票**（繁简归一后投票）为主，排期表推断兜底，前端可手动指定。
- `_classify_segment(...)`：逐段判定，**杂质优先删、保新闻为先**（详见迭代 v2.1 / v2.2）。
- `detect(...)`：跑规则 + DeepSeek 兜底模糊段 + bridge 蔓延 + VIP 检测，产出 `{segments, blocks, stats, target_column, vip}`。
- `build_plan(...)`：按源时间戳排序、组内合并保留段成 clip、安全余量、最短片段过滤。
- `build_llm_call(...)`：DeepSeek 兜底分类（纯文本，复用全局 text provider 配置）。
- `load_vip_names(config)`：优先读 `data/vip_persons.json`（Web 编辑），否则 config 打底。

逐段判定的标签（drop=删 / keep=留）：
| 标签 | 处理 | 说明 |
|---|---|---|
| `target` / `target_intro_outro` | 留 | 目标栏目角标/片头大标题命中 |
| `bridge` | 留 | 无角标但有连续解说、紧邻目标段的正片 |
| `other_column` | 删 | 出现别的栏目角标/名（如凤凰全球连线）|
| `sponsor` | 删 | 赞助/冠名卡（基本无新闻实质时）|
| `promo` | 删 | 预告/宣传（预告其他节目、含非目标《节目名》）|
| `ad` | 删 | 商业广告行动号召/购物话术 |
| `packaging_other` | 删 | 片头/台标包装（footage_types 含"片头包装"）|
| `station_id` | 删 | 无角标无语音的台标卡/垫片 |
| `unknown_drop` | 删 | 无角标、说不清、又不挨目标段 |

## 四、迭代记录（问题 → 根因 → 解决）

### v1：通用去广告（留新闻删广告）
- 思路：保留新闻、删广告/宣传/片头片尾，时序拼接。
- 局限：只是"留新闻"，没有"按栏目"概念。

### v2：改为「按栏目过滤」（只留目标栏目）
- **新模型**：从"留新闻"改为"只留目标栏目的拉片，其余全删"。
- **关键发现（地基）**：当时画面分析提示词 `vision_chunk.txt` 只输出"每帧镜头类型 + 画面描述"，**根本没提取画面文字/角标**——`screen_text`/`scene_type` 一直是空的，按角标过滤无从谈起。
- **解决**：增强 `vision_chunk.txt`，新增输出 `screen_text`（画面文字）和 `column_bug`（栏目角标），经 materialize → timeline → digest 透传；bump vision 提示词版本强制重跑。
- 配套：`[program_schedule]`（节目表）、`[vip_persons]`、目标栏目解析、VIP 检测 + Web 配置接口 `/api/vip-persons`、前端目标栏目输入 + 🔥/🍀 徽标 + 移除报告。

### v2.1：真机反馈「其他栏目广告/片头去不干净、太长」
复盘真机 `ad_detection.json` 定位多个根因并修复：

| 问题 | 根因 | 解决 |
|---|---|---|
| 真·正片被当其他栏目删 | **繁简不匹配**：凤凰画面是繁体"鳳凰聚焦"，而排期/目标是简体"凤凰聚焦"，`column_match` 失配 | 接入 **opencc t2s**，`_norm` 统一繁→简，角标投票/匹配全程繁简不敏感 |
| 短杂质（片头/台标/赞助/预告）混进正片段一起保留 | **60s 分段太粗**，短杂质常无 ASR，被并进相邻有角标的 60s 段，整段保留 | full_concat 强制 **chunk_seconds=10 / frame_interval=5**（让短杂质独立成段）|
| 挂着目标角标、却在预告其他节目的段被当正片留 | 角标"短路"了判断 | 识别 **《节目名》书名号**（不依赖排期收录）+ 预告话术，命中即判 promo 删；LLM 提示词去偏 |
| 片头/台标没删 | 判包装用了空的 `scene_type` | 改用有值的 **`footage_types`**（含"片头包装"）|
| 判定哲学整体过留 | "默认保留、证据不足才删" + bridge 无脑保留 | 改为**先正向删杂质**（赞助/预告/广告，即使带目标角标），再保留目标正片 |
| 0 时长碎段噪声 | 5 分钟源末尾空 chunk | seg_time 过滤 `end<=start` |

### v2.2：真机反馈「成片开头丢了'斯塔默辞职'那句」
- **复盘数据定位真凶**（不是抽帧、不是 bridge）：节目开场反复打"由华润集团赞助播出"，而开头新闻"斯塔默辞职"和赞助语**黏在同几个 60s 段里**；v2.1 的"赞助即删"把开头 3 段（0–180s）整段删了，头条被连带删掉，成片只能从第 180 秒开始。
- **解决（两处，ad_detection.py，PROMPT_VERSION→v4_news_first）**：
  1. **保新闻为先**：新增 `_residual_news_len()`（去掉话术+节目名+套话后剩余的中文字数）。赞助/预告/广告话术只在 `residual < min_news_chars`(默认 12) 即"基本是纯杂质"时才删；和大段新闻混在一起就**保留新闻**。其他栏目（异角标）仍一律删。
  2. **bridge 改为向目标段两侧"生长"**：旧版要求无角标段"前后都有目标"才留 → 开头/结尾的无角标正片留不住；改为从目标段沿相邻 undecided 段向前后蔓延、碰到 drop(杂质)段为止。开头第一句、结尾最后一句保住，插播广告/赞助（都是 drop 段）成为边界、不被带入。
- **真机数据复跑验证**：开头 3 段（含华润赞助 + 斯塔默辞职）现全部 `keep=target`，成片从"斯塔默辞职"开头开始；其他栏目/纯赞助卡/台标包装仍被正确删除。

## 五、关键设计取舍

- **目标栏目以角标为准**，与排期表不一致时用角标并在报告标来源（角标识别/排期推断/手动指定）。
- **赞助/冠名卡（含节目自己的华润赞助卡）要删**，但"保新闻为先"——和大段新闻混在一起时保留新闻（开头可能短暂露出几秒赞助卡画面，这是 60s 粒度下的预期代价）。
- **不精编**：只去杂质，正片一句不删，时长≈整集。
- **粒度 10s**：60s 切不开"插播在 60s 内的广告/片头"，故 full_concat 用更细的 10s。代价见"已知限制"。

extra_promo_keywords = []

## 八、已知限制与运维注意

1. **重跑 vs 新建任务（粒度）**：
   - 判定逻辑的修复（保新闻为先、繁简、bridge 生长）在 **60s 下就生效**——在旧任务上**从 `ad_detection` 步重跑**即可恢复开头、刷新去除效果（几分钟，画面分析已缓存，无需从头）。
   - 但 **10s 粒度只在新建任务时生效**：公共池 key 含 `chunk_seconds`，旧任务（60s 建池）重跑会复用 60s 池、且 `source_request.json` 仍是 60。要拿到 10s（把华润赞助卡那约 5 秒也切干净），需**重新选素材新建完整版任务**。
   - 「重跑也自动按新粒度重建公共池」未做（改动深、有风险）。
2. **公共池不与其它模式共享**：full_concat 用 10s、AI配音/视频重组用 60s，因 key 含 chunk_seconds 自动分到不同池——不会串，但同素材会被分析两遍，full_concat 那遍约 6× 画面调用，更慢更贵。
3. **角标识别可靠性**是上限：角标小、靠多模态画面分析读；读不到时回退排期 + 文案 + bridge。
4. **赞助卡短暂露脸**：60s 粒度下，和开头新闻同段的赞助卡画面会短暂保留（保新闻为先的取舍）；10s 下可切干净。
5. ASR（FunASR/SenseVoice）是按 chunk_seconds 整段转写、无句子级时间码，所以更细的裁切只能靠更细的 chunk，没有"在 60s 池上偷偷细切"的捷径。
