# 多源任务进度同步优化方案与代码修改指南

适用仓库：`angelOnly/AutomaticEditing`  
适用分支：`clean-highlight-reassembly`  
项目入口：`python run_web.py`  
重点问题：多源任务同时创建「AI配音解说」和「视频重组」时，后台日志持续运行，但 UI 进度条不跟随。

---

## 0. 给 Codex 的执行要求

请不要只用代码搜索。请优先按路径读取并修改以下文件：

1. `web_app.py`
2. `run_multisource_pipeline.py`
3. `newsclip_agent/pipeline.py`
4. `web_static/app.js`
5. `config.toml`，仅在需要新增配置项时修改

保持现有 Web 启动方式不变：

```bash
python run_web.py
```

不要重构整个项目，不要改任务目录结构，不要引入数据库，不要引入 WebSocket。优先用现有 `manifest.json` 机制解决问题。

---

## 1. 问题背景

当前系统支持两类生产模式：

- `ai_voiceover`：AI配音解说
- `highlight_reassembly`：视频重组

单视频任务时，`run_pipeline.py` 直接调用 `newsclip_agent/pipeline.py`，每一步状态都会写入当前任务目录：

```text
outputs/<task_id>/manifest.json
```

所以 UI 进度条正常。

多视频任务时，`web_app.py` 会调用：

```text
run_multisource_pipeline.py
```

多源流程会先创建公共分析目录：

```text
outputs/__common__/common_<source_key>/manifest.json
```

公共分析包括：

```text
source_prepare
metadata
audio_extract
frame_extract
chunk_build
asr
vision
timeline
timeline_digest
```

这些步骤真实运行时，进度写在 `outputs/__common__/common_xxx/manifest.json`。但是 UI 选中的是子任务：

```text
outputs/<task_id>_ai_voiceover/manifest.json
outputs/<task_id>_highlight_reassembly/manifest.json
```

公共分析未完成前，子任务 manifest 没有实时更新，所以 UI 看起来一直停在 `0/1`、`0/15` 或步骤 pending，但日志已经在跑。

---

## 2. 目标架构

目标不是让 UI 去读取 common 目录，也不是在 API 返回时临时合并 common manifest。

目标是：

```text
outputs/__common__/common_xxx/manifest.json
        ↓ 定时同步公共步骤状态
outputs/<task_id>_ai_voiceover/manifest.json
outputs/<task_id>_highlight_reassembly/manifest.json
        ↓
UI 只读子任务 manifest
```

也就是说：

1. common 目录仍然是公共分析的真实执行目录。
2. 每个子任务 manifest 都保存一份公共步骤的镜像状态。
3. UI 不需要知道 common 目录存在。
4. 服务重启后，子任务 manifest 已经落盘，UI 仍能展示最后进度。

---

修改完成后，多源任务运行时，子任务 manifest 应该类似：

## 4. 修改文件总览

| 文件 | 修改目的 |
|---|---|
| `web_app.py` | 创建多源任务时，初始化完整子任务 manifest，不再只写 `source_request.json` |
| `run_multisource_pipeline.py` | 后台线程定时同步 common manifest 到当前子任务 manifest |

| `config.toml` | 可选：新增 common 进度同步间隔配置 |

```python
    *,
    task_dir: Path,
    task_id: str,
    req: RunRequest,
    raw_source_items: list[dict[str, Any]],
    common_task_id: str,
    common_source_key: str,
) -> None:
    """Create a complete pending manifest for a multi-source child task.

    The actual common analysis runs under outputs/__common__/common_xxx,
    but the UI should only read the child task manifest. Therefore we create
    all expected steps here and mark reusable common steps explicitly.
    """
    manifest_path = task_dir / "manifest.json"
    if manifest_path.exists():
        return

    now = datetime.now().isoformat(timespec="seconds")
    common_steps = set(COMMON_REUSABLE_STEPS)
    steps: dict[str, dict[str, Any]] = {}

    for step in _step_order_for_production_mode(req.production_mode):
        item: dict[str, Any] = {
            "step_name": step,
            "status": "pending",
            "updated_at": now,
            "can_rerun": False,
        }
        if step in common_steps:
            item["common_progress"] = True
            item["common_task_id"] = common_task_id
        steps[step] = item

    write_json(
        manifest_path,
        {
            "task_id": task_id,
            "created_at": now,
            "updated_at": now,
            "status": "pending",
            "source_mode": "multi_source_pending",
            "source_video": "",
            "source_manifest": "",
            "source_videos": [],
            "production_mode": req.production_mode,
            "common_task_id": common_task_id,
            "common_source_key": common_source_key,
            "source_count": len(raw_source_items),
            "last_web_run_options": req.model_dump(),
            "steps": steps,
        },
    )
```

## 13. 新增同步函数

放在 `COMMON_REUSABLE_STEPS` 后面或 `_ensure_common_analysis()` 前面。

```python
def _sync_common_progress_to_child(
    *,
    common_dir: Path,
    task_dir: Path,
    request: dict[str, Any],
) -> None:
    """Mirror common analysis step statuses into one child task manifest.

    The common pipeline writes real progress to outputs/__common__/common_xxx.
    The Web UI reads outputs/<child_task>/manifest.json. This function keeps
    child manifest in sync without making the UI aware of common directories.
    """
    common_manifest = read_json(common_dir / "manifest.json", {})
    if not common_manifest:
        return

    child_manifest_path = task_dir / "manifest.json"
    child_manifest = read_json(child_manifest_path, {})
    now = datetime.now().isoformat(timespec="seconds")

    child_manifest.setdefault("task_id", task_dir.name)
    child_manifest.setdefault("created_at", now)
    child_manifest["updated_at"] = common_manifest.get("updated_at", now)
    child_manifest["common_task_id"] = common_dir.name
    child_manifest["common_source_key"] = request.get("common_source_key", "")
    child_manifest["production_mode"] = request.get(
        "production_mode",
        child_manifest.get("production_mode", "ai_voiceover"),
    )
    child_manifest["source_count"] = len(request.get("source_items") or [])
    child_manifest.setdefault("steps", {})

    common_steps = common_manifest.get("steps", {}) or {}

    for step in COMMON_REUSABLE_STEPS:
        common_step = common_steps.get(step)
        if not common_step:
            continue

        synced = dict(common_step)
        synced["common_progress"] = True
        synced["common_task_id"] = common_dir.name
        synced["reused_from"] = relpath(common_dir, ROOT)
        child_manifest["steps"][step] = synced

    for key in ("source_video", "source_mode", "source_manifest", "source_videos"):
        if common_manifest.get(key):
            child_manifest[key] = common_manifest[key]

    if common_manifest.get("status") == "failed":
        child_manifest["status"] = "failed"
        child_manifest["user_message"] = common_manifest.get("user_message", "")
    elif any((common_steps.get(step) or {}).get("status") == "running" for step in COMMON_REUSABLE_STEPS):
        child_manifest["status"] = "running"
    elif all(
        (common_steps.get(step) or {}).get("status") in {"success", "partial_success", "skipped"}
        for step in COMMON_REUSABLE_STEPS
        if step in common_steps
    ):
        # Common part is ready, but mode-specific steps may still be pending/running.
        child_manifest["status"] = child_manifest.get("status") or "running"

    write_json(child_manifest_path, child_manifest)
```

## 14. 新增后台同步线程

```python
def _start_common_progress_sync(
    *,
    common_dir: Path,
    task_dir: Path,
    request: dict[str, Any],
    interval_seconds: float = 2.0,
) -> threading.Event:
    stop_event = threading.Event()

    def loop() -> None:
        while not stop_event.is_set():
            try:
                _sync_common_progress_to_child(
                    common_dir=common_dir,
                    task_dir=task_dir,
                    request=request,
                )
            except Exception as exc:
                _append_common_log(common_dir, f"sync common progress to child failed: {exc}")
            stop_event.wait(interval_seconds)

    thread = threading.Thread(target=loop, daemon=True)
    thread.start()
    return stop_event
```

## 16. 修改 `_copy_common_outputs_to_task()`，避免覆盖模式专属步骤

当前函数会复制 common 的公共步骤到子任务 manifest。这个逻辑可以保留，但要保证只覆盖公共步骤，不要误删或覆盖模式专属步骤。

建议把这段逻辑改成更明确的版本：

```python
def _copy_common_outputs_to_task(*, common_dir: Path, task_dir: Path, request: dict[str, Any]) -> None:
    ensure_dir(task_dir)
    copied_dirs = ["input", "metadata", "preprocess", "asr", "vision", "timeline"]
    for name in copied_dirs:
        src = common_dir / name
        if not src.exists():
            continue
        dst = task_dir / name
        if dst.exists():
            shutil.rmtree(dst)
        shutil.copytree(src, dst)

    ensure_dir(task_dir / "input")
    write_json(task_dir / "input" / "source_request.json", request)

    common_manifest = read_json(common_dir / "manifest.json", {})
    manifest = read_json(task_dir / "manifest.json", {})
    now = datetime.now().isoformat(timespec="seconds")

    manifest.setdefault("task_id", task_dir.name)
    manifest.setdefault("created_at", now)
    manifest["updated_at"] = now
    manifest["common_task_id"] = common_dir.name
    manifest["common_source_key"] = request.get("common_source_key", "")
    manifest["production_mode"] = request.get("production_mode", manifest.get("production_mode", "ai_voiceover"))

    for key in ("source_video", "source_mode", "source_manifest", "source_videos"):
        if key in common_manifest:
            manifest[key] = common_manifest[key]

    manifest["reused_common_steps"] = COMMON_REUSABLE_STEPS
    manifest.setdefault("steps", {})

    for step in COMMON_REUSABLE_STEPS:
        status = dict((common_manifest.get("steps") or {}).get(step, {}))
        if status:
            status["reused_from"] = relpath(common_dir, ROOT)
            status["common_progress"] = True
            status["common_task_id"] = common_dir.name
            manifest["steps"][step] = status

    write_json(task_dir / "manifest.json", manifest)
```

## 20. 修改 `step_vision()`，运行中写 chunk summary

找到 `step_vision()` 里这段：

```python
with ThreadPoolExecutor(max_workers=max_workers) as executor:
    futures = [executor.submit(process_one_chunk, chunk) for chunk in chunks_to_process]
    for future in as_completed(futures):
        record = future.result()
```

替换为：

```python
max_workers = max(1, int(self.options.vision_max_workers or 1))
total_chunks = len(chunks_to_process) + len(chunk_records)
with ThreadPoolExecutor(max_workers=max_workers) as executor:
    futures = [executor.submit(process_one_chunk, chunk) for chunk in chunks_to_process]
    for future in as_completed(futures):
        record = future.result()
        chunk_records.append(record)

        success = sum(1 for c in chunk_records if c["status"] in {"success", "reused", "manual_edited"})
        failed = sum(1 for c in chunk_records if c["status"] == "failed")
        processed = len(chunk_records)

        self.manifest.setdefault("steps", {}).setdefault("vision", {})
        self.manifest["steps"]["vision"].update(
            {
                "step_name": "vision",
                "status": "running",
                "updated_at": now_iso(),
                "can_rerun": False,
                "current_chunk": record.get("chunk_id", ""),

                    "processed_chunks": processed,
                    "success_chunks": success,
                    "failed_chunks": failed,
```

- `chunk_records` 在进入 executor 前已经包含 reused chunk。
- `total_chunks = len(chunks_to_process) + len(chunk_records)` 必须放在 executor 前。
- 如果 `failed_only` 或指定 chunk 重跑，也能正常统计。

# 第四部分：修改 `web_static/app.js`

## 21. 当前问题

前端全局 `STEPS` 依赖页面控件 `productionMode`。但用户点击历史任务或同时跑两个模式时，控件状态可能和 manifest 的真实 `production_mode` 不一致。

另外，公共步骤即使同步到子任务 manifest，UI 上最好显示“公共分析中 / 复用公共分析结果”。

## 22. 新增按 manifest 获取步骤表的函数

加入：

```javascript
function stepsForManifest(manifest) {
  const mode =
    manifest?.production_mode ||
    manifest?.last_run_options?.production_mode ||
    manifest?.last_web_run_options?.production_mode ||
    $("productionMode")?.value ||
    "ai_voiceover";
  return mode === "highlight_reassembly" ? HIGHLIGHT_REASSEMBLY_STEPS : AI_VOICEOVER_STEPS;
}
```

## 23. 修改 `renderManifest()` 使用局部步骤表

在 `renderManifest()` 里找到使用全局 `STEPS` 的地方。建议开头增加：

```javascript
const activeSteps = stepsForManifest(manifest);
```

然后把：

```javascript
STEPS.map(...)
STEPS.length
```

改成：

```javascript
activeSteps.map(...)
activeSteps.length
```

重点修改这些位置：

```javascript
const rows = activeSteps.map((step) => { ... }).join("");
const visibleEntries = activeSteps.map((step) => [step, steps[step] || {}]);
updateProgress(done, activeSteps.length, completed, skipped, failed);
$("metricSteps").textContent = `${done}/${activeSteps.length}（成功 ${completed}，跳过 ${skipped}）`;
```

这样 UI 展示某个任务时，以任务 manifest 为准，不受当前页面模式按钮影响。

## 24. 修改 `stepNote()` 显示 common 和 vision chunk 进度

找到：

```javascript
function stepNote(step, item = {}) {
  if (!item || item.status === "pending") return "";
  if (item.status === "skipped") return skippedReasonText(item.reason, step);
  return item.error || item.reason || "";
}
```

替换为：

```javascript
function stepNote(step, item = {}) {
  if (!item) return "";

  if (step === "vision" && item.summary) {
    const s = item.summary || {};
    const total = Number(s.total_chunks || 0);
    const processed = Number(s.processed_chunks || 0);
    const failed = Number(s.failed_chunks || 0);
    if (total && item.status === "running") {
      return `画面 chunk ${processed}/${total}${failed ? `，失败 ${failed}` : ""}`;
    }
  }

  if (item.common_progress && item.status === "running") return "公共分析中";
  if (item.common_progress && item.status === "success") return "复用公共分析结果";
  if (item.common_progress && item.status === "partial_success") return "公共分析部分成功";

  if (!item.status || item.status === "pending") return "";
  if (item.status === "skipped") return skippedReasonText(item.reason, step);
  return item.error || item.reason || "";
}
```

# 第八部分：容易踩坑的点

## 32. 不要让 UI 直接读 common 目录

不要新增前端接口让 UI 切换到 common task。这样会让左侧任务列表、任务详情、成片预览都变复杂。

正确做法是：

```text
common 进度同步到子任务 manifest
UI 只读子任务 manifest
```

## 33. 不要在 `/api/tasks/{task_id}/manifest` 临时合并 common

临时合并能快速解决展示问题，但数据不落盘，服务重启后不稳定，也会让 API 逻辑变复杂。

本方案要求同步落盘到子任务 manifest。

## 34. 不要覆盖模式专属步骤

同步 common 进度时，只允许覆盖：

```text
source_prepare
metadata
audio_extract
frame_extract
chunk_build
asr
vision
timeline
timeline_digest
```

不要覆盖：

```text
content_analysis
short_video_edit_plan
voiceover_script
tts
subtitles
cut_plan
render
video_understanding
highlight_detection
highlight_reassembly_plan
reassembly_cut_plan
reassembly_render
```

## 35. 注意 manifest 并发写入

同一个子任务中：

- `run_multisource_pipeline.py` 同步线程会写 manifest
- 后续 `pipeline.py` 模式专属步骤也会写 manifest

所以同步线程必须在 `_run_mode_specific_pipeline()` 前停止。上面的 `finally: stop_sync.set()` 可以保证公共分析后同步线程停止。

不要让 common 同步线程和模式专属 pipeline 同时长期写同一个 manifest。

## 36. 注意 common 已完成时的复用路径

如果 common 已经完成，`_ensure_common_analysis()` 会直接 return。同步线程仍应至少同步一次，确保新建的另一个子任务也能拿到公共步骤状态。

上面 main 分支中，在 `_ensure_common_analysis()` 前后都调用了 `_sync_common_progress_to_child()`，就是为了覆盖这个场景。
