# 高光片段重组模式：产品需求文档 v1

## 1. 产品定位

“高光片段重组模式”是 Phoenix Newsclip Agent 在现有“AI 配音生成新解说视频”之外新增的一条轻量生产链路。

它的核心目标不是重新写文案、不是生成 TTS、也不是用 AI 配音重构叙事，而是：

> 从一条新闻长视频中识别真正有新闻价值和传播价值的高光片段，按新闻编辑逻辑重新排序、裁切和拼接，生成一条或多条“保留原声的高光重组视频”。

该模式适合以下场景：

```text
1. 原视频已有完整播报、记者连线、嘉宾发言或现场原声，不需要重新配音。
2. 编辑只想快速得到一版“精选片段合集”或“事件脉络重组”。
3. 原视频信息已经清楚，AI 主要负责找点、排序、裁切，而不是改写表达。
4. 需要尽量保留新闻现场感、权威讲话、记者连线和节目原始表达。
5. 想降低 TTS 成本、减少配音失败、减少文案事实改写风险。
```

它与现有 AI 配音模式的区别如下：

| 对比项 | AI 配音新解说视频 | 高光片段重组模式 |
|---|---|---|
| 核心产物 | 新文案 + AI 配音 + 视频画面 | 原视频高光片段重新组合 |
| 声音来源 | AI 配音为主，原声可选 | 原视频原声为主 |
| 是否重写文案 | 是 | 否，最多生成标题/说明/片段摘要 |
| 是否 TTS | 是 | 否 |
| 是否生成字幕 | 可选，可复用原字幕/ASR 摘要 | 可选，不作为主流程必需 |
| 剪辑重点 | 画面服务于新解说 | 原片段自身的信息完整性和节奏 |
| 主要风险 | AI 文案不准、TTS 与画面错位 | 断章取义、上下文缺失、片段衔接突兀 |

## 2. 用户需求

### 2.1 用户是谁

第一阶段用户主要是新闻编辑、短视频运营、内容策划、剪辑助理。

他们不一定想让 AI 代替自己写一条新稿，而是希望 AI 先帮他们完成：

```text
1. 从长视频里找出最值得看的几段。
2. 判断哪些片段可以独立成片，哪些需要合并。
3. 自动裁掉冗余铺垫、重复寒暄、无信息过渡。
4. 按新闻逻辑重组片段顺序。
5. 快速导出一版可审看的粗剪视频。
```

### 2.2 用户核心痛点

当前新闻长视频的人工处理成本主要在“看”和“判断”：

```text
哪里是真高光？
哪段只是铺垫？
哪段有事实但缺上下文？
哪段讲话不能只截一半？
多段高光应该按原顺序拼，还是按事件逻辑重排？
剪出来以后观众能不能直接看懂？
```

高光片段重组模式要解决的是这些编辑判断问题，而不是单纯调用 FFmpeg 裁切。

## 3. 产品目标

### 3.1 总体目标

输入一条新闻长视频，系统自动完成：

```text
长视频理解
↓
高光片段识别
↓
片段完整性判断
↓
片段合并/舍弃/排序
↓
生成重组方案
↓
自动裁切拼接
↓
输出原声高光重组视频
```

### 3.2 输出目标

每个任务至少输出：

```text
1. candidate_clips.json：候选高光片段。
2. highlight_reassembly_plan.json：高光重组方案。
3. reassembly_cut_plan.json：可执行裁切拼接计划。
4. highlight_reassembly_draft.mp4：原声高光重组粗剪视频。
5. reassembly_review_report.json：风险、上下文、断章取义检查报告。
```

可选输出：

```text
1. 每个高光片段的独立预览视频。
2. 重组视频的标题、摘要、封面文案。
3. 片段之间的转场字幕或章节标题。
4. 基于 ASR 的内嵌字幕。
5. 竖版/横版两个比例版本。
```

## 4. 用户使用流程

### 4.1 Web 入口

在 Web 页面新增“生产模式”选项：

```text
生产模式：
- AI 配音解说视频
- 高光片段原声重组
```

用户选择“高光片段原声重组”后，界面应隐藏或弱化以下选项：

```text
TTS 必须成功
AI 配音音轨策略
允许证据原声
配音文案生成
字幕跟随 TTS
```

同时突出以下选项：

```text
目标总时长
输出条数
片段排序方式
是否保留原始顺序
是否允许跨段重组
是否生成章节转场字幕
是否导出单片段预览
```

### 4.2 推荐默认配置

```text
生产模式：高光片段原声重组
输出方式：单条综合版
目标总时长：60-120 秒
最多片段数：3-8 段
最短片段：5 秒
最长片段：45 秒
默认排序：新闻逻辑优先，必要时保持原始时间顺序
声音策略：保留原视频原声
字幕策略：默认不强制烧录，可生成 SRT
转场策略：默认硬切，必要时 0.15-0.3 秒淡入淡出
```

### 4.3 编辑操作路径

```text
1. 选择视频。
2. 选择“高光片段原声重组”。
3. 点击开始分析。
4. 系统输出候选高光和重组方案。
5. 编辑在 Web 中预览：
   - 候选高光列表
   - 推荐排序
   - 每段使用原因
   - 风险提示
6. 编辑可选择：
   - 直接生成重组视频
   - 取消某个片段
   - 调整片段顺序
   - 修改片段起止时间
   - 只重跑高光识别
   - 只重跑重组规划
7. 系统输出原声高光重组视频。
```

## 5. 什么是“高光片段”

在新闻视频里，高光不是娱乐化爆点，而是具备以下特征的片段：

```text
1. 有明确新闻事实。
2. 有最新进展或关键变化。
3. 有现场画面、权威表态、记者连线、嘉宾关键判断等支撑。
4. 信息密度高，不只是寒暄或过渡。
5. 能独立表达一个相对完整的新闻点。
6. 被截取后不会误导观众。
7. 具备短视频观看价值。
8. 风险可控，必要时能提示人工复核。
```

### 5.1 高光片段类型

#### A. 核心事实型

适合放在开头，用来快速说明发生了什么。

判断标准：

```text
谁、何时、何地、做了什么、造成什么影响。
```

#### B. 最新进展型

适合用于突发新闻、外交、军事、灾害、政策类内容。

判断标准：

```text
是否出现新变化、新表态、新数据、新行动。
```

#### C. 现场画面型

适合用于提高视频可看性。

判断标准：

```text
画面是否直接展示现场状态、冲突、行动、灾害、发布会、会议、连线等。
```

#### D. 权威表态型

适合用于保留原声。

判断标准：

```text
发言人、政府机构、警方、军方、国际组织、企业高管、当事人等关键主体是否表达核心信息。
```

#### E. 记者连线型

适合用于重组视频中承担解释功能。

判断标准：

```text
记者是否说明现场情况、事件背景、当地反应、后续走势。
```

#### F. 嘉宾解读型

适合放在事实之后，承担“为什么重要”的功能。

判断标准：

```text
嘉宾是否提出清晰判断、解释原因、梳理影响、预测后续。
```

#### G. 时间线梳理型

适合用于综合版。

判断标准：

```text
是否能帮助观众理解事件从发生到变化的顺序。
```

### 5.2 不应选为高光的片段

```text
1. 纯开场寒暄。
2. 主持人过渡语。
3. 重复上一段的信息。
4. 只有情绪但没有事实。
5. 只有结论但没有主体和上下文。
6. 半句话、断句、语义不完整的讲话。
7. 画面和 ASR 明显不匹配的片段。
8. 资料画面容易被误认为现场画面的片段。
9. 风险极高且无法通过上下文修复的片段。
```

## 6. 高光评分体系

系统对每个候选片段输出 0-10 分评分。

```json
{
  "news_value_score": 9,
  "visual_value_score": 8,
  "audio_value_score": 8,
  "context_integrity_score": 7,
  "independence_score": 8,
  "reassembly_value_score": 9,
  "risk_score": 2,
  "overall_score": 8.4
}
```

### 6.1 评分维度

| 维度 | 含义 | 高分标准 |
|---|---|---|
| news_value_score | 新闻价值 | 直接包含核心事实、最新进展、权威信息 |
| visual_value_score | 画面价值 | 画面有现场感、识别度、信息量 |
| audio_value_score | 原声价值 | 原声清楚、有完整语义、有新闻证据价值 |
| context_integrity_score | 上下文完整性 | 单独截取后不误导 |
| independence_score | 独立成片能力 | 不依赖大量前文也能看懂 |
| reassembly_value_score | 重组价值 | 放进合集后能推动叙事 |
| risk_score | 风险分 | 越高越危险，涉政、涉战、灾害伤亡、争议表态需提高 |

### 6.2 推荐等级

```text
S 级：强烈推荐，优先进入重组视频。
A 级：推荐，可进入重组视频。
B 级：备选，可用于补上下文或补节奏。
C 级：不推荐，默认不进入成片。
```

## 7. 高光片段边界判断

高光片段重组最容易出问题的是“切点”。因此产品上必须要求模型判断片段边界。

### 7.1 起点标准

片段起点应满足：

```text
1. 不从半句话开始。
2. 不从代词、转折词、承接词开始，例如“这也说明”“所以他们”。
3. 尽量从一个完整事实、问题、表态或画面动作开始。
4. 如果原视频有主持人导语，可保留必要的 1-3 秒上下文。
5. 如果是讲话，起点应在完整语义单元开头。
```

### 7.2 终点标准

片段终点应满足：

```text
1. 不在半句话中结束。
2. 尽量包含一句完整结论或转折。
3. 如果后文是重复内容，可以提前结束。
4. 如果后文补充了关键信息，不能过早切断。
5. 如果是现场动作，应保留动作完成或画面结果。
```

### 7.3 边界扩展规则

```text
默认向前扩展 0.3-1.0 秒，避免切掉开头语音。
默认向后扩展 0.5-1.5 秒，避免切掉结尾语气。
如果检测到 ASR 句子未完整，向前/向后扩展到完整句边界。
如果前后片段相邻且间隔小于 2 秒，优先合并。
```

## 8. 高光片段如何重组

### 8.1 重组目标

重组不是简单把最高分片段按分数排序拼起来，而是要形成一条观众能看懂的视频。

一条好的重组视频应满足：

```text
1. 开头 3-8 秒能让观众知道核心事件。
2. 中段按照事实推进或逻辑关系展开。
3. 片段之间没有明显断裂。
4. 不因重排改变原意。
5. 结尾有相对完整的收束。
6. 总时长符合短视频观看习惯。
```

### 8.2 推荐重组结构

#### 结构 A：事件快讯版

```text
核心事实 → 现场画面 → 官方/当事方回应 → 最新进展
```

适合突发、外交、军事、灾害、社会事件。

#### 结构 B：现场连线版

```text
主持人导语/核心事实 → 记者现场说明 → 关键画面 → 后续影响
```

适合记者连线、外派报道。

#### 结构 C：观点解读版

```text
核心问题 → 嘉宾关键判断 → 原因解释 → 影响/后续
```

适合访谈、评论、专题。

#### 结构 D：时间线版

```text
事件起点 → 关键转折 → 多方回应 → 当前状态
```

适合复杂事件。

#### 结构 E：多高光合集版

```text
高光 1 → 高光 2 → 高光 3 → 高光 4
```

适合节目精华、发布会要点、会议多议题摘要。

### 8.3 排序原则

默认采用“新闻逻辑优先，原始顺序兜底”：

```text
1. 如果原视频已经是清晰新闻结构，保持原始时间顺序。
2. 如果原视频铺垫较长，把核心事实/强画面前置。
3. 如果多段属于同一事件链，按事件发展顺序排列。
4. 如果是多议题会议，可按主题分组排列。
5. 如果是嘉宾访谈，可把核心观点前置，再补原因。
6. 如果重排会造成误解，则必须保持原始顺序。
```

### 8.4 片段合并规则

以下情况应合并：

```text
1. 两段属于同一个完整语义单元。
2. 两段时间间隔小于 2 秒，中间只是停顿或过渡。
3. 第一段提出问题，第二段给出答案。
4. 第一段是画面，第二段是解释，单独看都不完整。
5. 拆开会造成断章取义。
```

以下情况应拆开：

```text
1. 两段属于不同新闻点。
2. 中间有明显冗余、重复、寒暄。
3. 一段是事实，一段是评论，且可独立表达。
4. 一段风险较高，需要单独人工审核。
```

### 8.5 舍弃规则

即使片段分数较高，也要在以下情况舍弃：

```text
1. 原声听不清，且无法通过字幕/上下文修复。
2. 片段依赖大量前文，短视频中无法交代。
3. 片段会改变原视频表达立场。
4. 片段与已选片段信息重复。
5. 加入后导致总时长超过目标太多。
6. 风险超过阈值，且没有人工确认。
```

## 9. 输出视频形态

### 9.1 单条综合版

默认优先支持。

```text
适用：一条长视频围绕一个主题，内部有多个高光点。
推荐时长：60-120 秒。
片段数：3-8 段。
```

### 9.2 多条拆分版

```text
适用：一条长视频里有多个独立新闻点。
推荐条数：2-5 条。
每条时长：30-90 秒。
```

### 9.3 单片段高光版

```text
适用：某一段本身非常完整，例如发布会关键表态、记者现场连线、嘉宾金句。
推荐时长：15-60 秒。
```

## 10. 风险控制

高光重组模式必须重点控制“断章取义”。

### 10.1 必须标记的风险

```text
1. 涉及时政、外交、战争、军警、灾害、伤亡、公共安全。
2. 嘉宾观点可能被误认为事实。
3. 资料画面可能被误认为现场画面。
4. 片段只保留结论，缺少前提。
5. 片段经过重排后可能改变因果关系。
6. 多方表态只保留一方，可能不平衡。
7. 标题/字幕可能放大原意。
```

### 10.2 风险动作

```text
低风险：可自动生成粗剪。
中风险：生成粗剪，但标记人工审核。
高风险：不自动进入最终成片，只输出候选方案。
```

## 11. 验收标准

### 11.1 产品验收

```text
1. 能从 10-30 分钟新闻视频中输出 3-10 个候选高光片段。
2. 能解释每个片段为什么是高光。
3. 能判断哪些片段应合并、舍弃、前置、后置。
4. 能生成 1 条 60-120 秒左右的原声重组视频。
5. 重组视频不依赖 AI 配音也能看懂。
6. 片段起止点不明显切半句话。
7. 输出结果能在 Web 中预览、查看、重跑。
```

### 11.2 编辑体验验收

```text
1. 编辑可以一眼看到候选片段、评分、推荐理由。
2. 编辑可以知道为什么某些片段没进入成片。
3. 编辑可以只重跑高光识别或重组规划。
4. 编辑可以预览粗剪视频和中间 JSON。
5. 编辑可以下载/打开最终重组视频。
```

## 12. 第一版边界

第一版不做：

```text
1. 不做 AI 配音。
2. 不重写新闻解说文案。
3. 不做复杂包装动画。
4. 不做剪映/PR 工程导出。
5. 不做自动发布。
```

第一版必须做：

```text
1. 复用现有 ASR、抽帧、多模态理解、时间轴、高光识别能力。
2. 新增高光重组规划。
3. 新增原声重组 cut_plan。
4. 新增原声渲染。
5. Web 中新增模式入口。
6. 支持缓存、重跑和版本查看。
```
