# 原片列表状态更新问题：优化方案与代码修改意见

## 一、问题概述

当前 Web 工作台右侧「视频预览」区域有两个 Tab：

- 「最新成片」
- 「原片」

用户在「本次剪辑素材」中连续添加多个远程视频源后，出现两个明显问题：

1. **未点击「原片」按钮前，原片列表不稳定**  
   页面右侧默认停留在「最新成片」Tab，下面列表标题仍是「成片列表」，内容显示「当前任务还没有生成粗剪视频」。此时即使左侧已经加入多个视频源，右侧并不会稳定展示这些原片源列表。

2. **点击多个视频源后，原片列表刷新后会消失**  
   连续点击远程素材加入「本次剪辑素材」后，右侧原片预览有时会短暂出现，但随后被刷新逻辑覆盖，重新变成「最新成片」的空状态，表现为“显示一会就消失”。

补充现象：

- 点击「移除」素材时，原片列表状态能跟着变化。
- 这说明 `sourceBasket` 本身的数据维护基本没问题，问题主要发生在“添加素材后的预览状态切换”和“自动刷新/列表刷新覆盖预览区域”之间。

---

## 二、当前代码现状

### 2.1 页面结构

`web_static/index.html` 中，「视频预览」区域使用同一套 DOM 同时承载成片列表和原片列表：

```html
<button id="openDraft" class="active">最新成片</button>
<button id="openSource">原片</button>
<video id="videoPreview" controls poster=""></video>
<div class="draft-box">
  <div class="draft-title">成片列表</div>
  <div id="draftList" class="draft-list">当前任务还没有生成粗剪视频。</div>
</div>
```

问题点：

- `draftList` 既被用来渲染「成片列表」，也被用来渲染「原片列表」。
- `.draft-title` 文案是静态的“成片列表”，没有跟随 Tab 状态切换。
- 只要某个刷新函数调用了 `renderDraftList()` 或 `loadLatestDraft()`，就可能把原片列表覆盖成“当前任务还没有生成粗剪视频”。

---

### 2.2 前端全局状态

`web_static/app.js` 中的状态包括：

```js
const state = {
  selectedVideo: null,
  selectedRemoteVideo: null,
  sourceBasket: [],
  selectedTask: null,
  previewMode: "draft",
  manifest: null,
  latestDraft: null,
  drafts: [],
  remoteVideos: [],
};
```

其中：

- `state.sourceBasket` 是本次剪辑素材列表。
- `state.previewMode` 控制当前右侧预览是 `draft` 还是 `source`。
- 默认值是 `draft`，所以页面初始总是偏向展示「最新成片」。

---

### 2.3 添加本地素材逻辑

当前 `addLocalSourceToBasket(video)` 会：

```js
state.sourceBasket.push(...);
state.selectedVideo = video;
state.selectedRemoteVideo = null;
renderSourceBasket();
updateActiveTitleForSources();
playSourceVideo();
```

这里会调用 `playSourceVideo()`，所以添加本地素材后理论上会切到原片预览。

---

### 2.4 添加远程素材逻辑

当前 `addRemoteSourceToBasket(video)` 会：

```js
state.sourceBasket.push(...);
state.selectedRemoteVideo = video;
state.selectedVideo = null;
renderSourceBasket();
updateActiveTitleForSources();
playSourceVideo();
```

随后远程素材列表点击事件又会继续执行：

```js
item.addEventListener("click", () => {
  addRemoteSourceToBasket(video);
  selectRemoteVideo(video);
});
```

也就是说，点击远程素材时实际触发顺序是：

```text
addRemoteSourceToBasket(video)
  -> playSourceVideo()
      -> 渲染 sourceBasket 原片列表

selectRemoteVideo(video)
  -> applyDefaultControls()
  -> clearTaskPanels()
  -> 直接设置 videoPreview 为远程 preview_url
  -> loadVideos()
  -> loadTasks()
  -> renderRemoteVideos()
```

这里存在状态覆盖风险：

- `addRemoteSourceToBasket()` 已经切到了原片模式。
- `selectRemoteVideo()` 又把任务、manifest、控制项重置了一遍。
- `clearTaskPanels()` 很可能会把右侧列表恢复为默认空状态。
- `loadVideos()`、`loadTasks()`、`renderRemoteVideos()` 会继续刷新页面，导致刚渲染好的原片列表被覆盖。

这就是“原片列表显示一会又消失”的主要原因。

---

### 2.5 移除素材逻辑为什么正常

当前 `updateSourceBasketItem(id, action)` 在移除、上移、下移后会执行：

```js
renderSourceBasket();
updateActiveTitleForSources();
playSourceVideo().catch((error) => console.warn("素材预览刷新失败", error));
```

这个逻辑比较干净：

- 没有再调用 `selectRemoteVideo()`。
- 没有 `applyDefaultControls()`。
- 没有 `clearTaskPanels()`。
- 没有额外的 `loadTasks()` / `loadVideos()` 覆盖预览区。

所以移除时原片列表能正常跟着变化。

---

## 三、问题根因

### 根因 1：远程素材点击同时做了“加入素材篮”和“选中远程素材预览”两件事

现在远程列表点击事件是：

```js
addRemoteSourceToBasket(video);
selectRemoteVideo(video);
```

这两个函数职责冲突：

- `addRemoteSourceToBasket()` 的语义是：把素材加入本次剪辑列表，并刷新本次剪辑源预览。
- `selectRemoteVideo()` 的语义更像：单独选中远程素材，并重置当前任务上下文。

当用户的操作目标是“添加到本次剪辑素材”时，不应该再执行“清空任务面板 / 重置控制项 / 单独预览远程素材”的逻辑。

---

### 根因 2：`draftList` 被成片列表和原片列表复用，刷新时容易互相覆盖

`renderDraftList()` 会写：

```js
box.textContent = "当前任务还没有生成粗剪视频。";
```

`renderSourceVideoList()` 也写同一个 `draftList`：

```js
box.innerHTML = source-item buttons...
```

因此只要刷新流程里走到 `loadLatestDraft()` / `renderDraftList()`，原片列表就会被覆盖。

---

### 根因 3：预览区没有明确的“用户当前意图”保护

当前代码只有 `state.previewMode`，但没有区分：

- 用户主动点击了「最新成片」
- 用户主动点击了「原片」
- 用户正在添加素材，系统应自动保持原片预览
- 后台自动刷新不应该改变预览区

虽然 `autoRefreshWorkspace()` 传了 `updatePreview: false`，但手动刷新、添加素材后的局部刷新、远程列表刷新仍可能间接覆盖右侧区域。

---

## 四、优化目标

### 目标 1：添加素材时，右侧应稳定进入「原片」模式

用户从本地素材或远程素材加入「本次剪辑素材」后，右侧应立即展示：

```text
原片列表
1. 第一个素材
2. 第二个素材
3. 第三个素材
...
```

不应该被“当前任务还没有生成粗剪视频”覆盖。

---

### 目标 2：原片列表内容应始终以 `sourceBasket` 为第一优先级

只要 `state.sourceBasket.length > 0`，右侧「原片」Tab 的列表就应该直接来自 `sourceBasket`，而不是任务 manifest 或成片 drafts。

优先级建议：

```text
1. state.sourceBasket 有内容：显示本次剪辑素材源列表
2. state.selectedTask 有内容：从 /api/tasks/{task_id}/source-videos 加载任务原片列表
3. state.selectedRemoteVideo 有内容：预览单个远程素材
4. state.selectedVideo 有内容：预览单个本地素材
5. 什么都没有：提示请选择原片或任务
```

---

### 目标 3：成片列表和原片列表的标题、空状态要分开

当 `previewMode === "draft"`：

```text
成片列表
当前任务还没有生成粗剪视频。
```

当 `previewMode === "source"`：

```text
原片列表
当前还没有可预览的原片，请先加入素材。
```

在 `state` 里增加：


修改后：

```js
const state = {

  selectedRemoteVideo: null,
```

含义：

## 6.3 修改 Tab 点击事件

当前：

```js
$("openSource").addEventListener("click", () => {
  playSourceVideo();
});

$("openDraft").addEventListener("click", () => {
  setPreviewMode("draft");
  ...
});
```

建议改成：

```js
$("openSource").addEventListener("click", () => {
  state.previewIntent = "user-source";
  playSourceVideo();
});

$("openDraft").addEventListener("click", () => {
  state.previewIntent = "user-draft";
  setPreviewMode("draft");
  if (state.drafts.length) {
    renderDraftList();
    playDraft(state.drafts[0]);

    playDraft(state.latestDraft);

    renderDraftList();
  }
});
```

重点：

- 用户点「原片」后，后续刷新不要轻易切回「最新成片」。
- 用户点「最新成片」后，才允许显示成片空状态。

## 6.5 修改远程素材点击事件：不要再调用 `selectRemoteVideo()` 覆盖预览

当前 `renderRemoteVideos()` 里：

```js
item.addEventListener("click", () => {
  addRemoteSourceToBasket(video);
  selectRemoteVideo(video);
});
```

建议改成：

```js
item.addEventListener("click", () => {
  addRemoteSourceToBasket(video);
  renderRemoteVideos();
});
```

原因：

- 点击远程素材在当前交互设计下就是“加入本次剪辑素材”。
- 加入素材后应以 `sourceBasket` 为准展示原片列表。
- 不应该再执行 `selectRemoteVideo()` 里的 `applyDefaultControls()`、`clearTaskPanels()`、`loadTasks()` 等副作用。

如果仍然希望支持“只预览远程素材但不加入素材篮”，建议后续另加一个小按钮，例如：

```text
预览
加入
```

但当前不要混在同一个 click 事件里。

## 6.6 修改 `addRemoteSourceToBasket()`

当前：

```js
function addRemoteSourceToBasket(video) {
  const key = video.remote_id || String(video.id || video.name || "");
  if (...) return;
  state.sourceBasket.push(...);
  state.selectedRemoteVideo = video;
  state.selectedVideo = null;
  renderSourceBasket();
  updateActiveTitleForSources();
  playSourceVideo();
}
```

建议改成：

```js
function addRemoteSourceToBasket(video) {
  const key = video.remote_id || String(video.id || video.name || "");
  const exists = state.sourceBasket.some(
    (item) =>
      item.source_type === "remote_ucms" &&
      (item.remote_video.remote_id || item.remote_video.id || item.remote_video.name) === key
  );

  if (!exists) {
    state.sourceBasket.push({
      id: makeSourceId(),
      source_type: "remote_ucms",
      remote_video: video,
      display_name: video.display_name || video.name || "远程素材",
    });
  }

  state.previewIntent = "basket";
  state.previewMode = "source";
  state.selectedRemoteVideo = video;
  state.selectedVideo = null;
  state.selectedTask = null;
  state.manifest = null;

  renderSourceBasket();
  updateActiveTitleForSources();
  clearTaskPanels({ keepPreview: true });
  playSourceVideo().catch((error) => console.warn("素材预览刷新失败", error));
}
```

注意：这里引用了 `clearTaskPanels({ keepPreview: true })`，下面需要一起改。

## 6.8 修改 `clearTaskPanels()`，避免清掉原片预览

需要找到当前 `clearTaskPanels()` 函数。建议改为支持参数：

```js
function clearTaskPanels(options = {}) {
  const { keepPreview = false } = options;

  state.manifest = null;
  state.activeJob = null;
  state.latestDraft = null;
  state.drafts = [];

  $("stepTable").innerHTML = "";
  $("fileList").innerHTML = "";
  $("fileViewer").textContent = "选择左侧任务或文件后显示内容。";
  $("logViewer").textContent = "暂无运行日志。";
  updateJobMessage("");
  updateStopJobButton();

  if (!keepPreview) {
    state.previewMode = "draft";
    state.previewIntent = "auto";
    $("videoPreview").removeAttribute("src");
    renderDraftList();
  }

  syncPreviewTabs();
}
```

如果当前项目里的 `clearTaskPanels()` 逻辑不同，原则是：

```text
添加/调整 sourceBasket 时，不要清空 videoPreview，不要重置 draftList，不要切回 draft。
选择任务或删除任务时，可以完整清空。
```

## 6.9 修改 `loadLatestDraft()`：原片模式下绝不覆盖列表

当前逻辑已有：

```js
if (state.previewMode !== "draft") return;
```

建议再加强：

```js
async function loadLatestDraft(taskId, options = {}) {
  const { updatePreview = true } = options;
  const drafts = await api(`/api/tasks/${taskId}/drafts`);
  state.drafts = drafts;
  state.latestDraft = drafts[0] || { exists: false, file: "", url: "" };

  if (state.previewMode !== "draft" || state.previewIntent === "basket" || state.previewIntent === "user-source") {
    return;
  }

  renderDraftList();
  if (!updatePreview) return;

  if (drafts.length) {
    playDraft(drafts[0]);
  } else {
    renderDraftList();
  }
}
```

## 6.10 修改 `renderDraftList()`：只负责成片列表

当前 `renderDraftList()` 会直接写空状态。建议明确它只在 draft 模式生效：

```js
function renderDraftList() {
  if (state.previewMode !== "draft") return;

  const box = $("draftList");
  if (!box) return;
  updatePreviewListTitle();

  if (!state.drafts.length) {
    box.innerHTML = `<div class="empty-row">当前任务还没有生成粗剪视频。</div>`;
    return;
  }

  box.innerHTML = state.drafts
    .map(
      (draft, index) => `<button class="draft-item ${index === 0 ? "active" : ""}" data-index="${index}">
        <strong>${escapeHtml(draft.file)}</strong>
        <span>${draft.size_mb} MB</span>
      </button>`
    )
    .join("");

  document.querySelectorAll(".draft-item").forEach((item) => {
    item.addEventListener("click", () => playDraft(state.drafts[Number(item.dataset.index)]));
  });
}
```

## 6.11 修改 `renderSourceVideoList()`：只负责原片列表

建议改成：

```js
function renderSourceVideoList(sources) {
  const box = $("draftList");
  if (!box) return [];

  state.previewMode = "source";
  syncPreviewTabs();

  const items = (sources || [])
    .filter((source) => source?.url)
    .map((source, index) => ({ ...source, list_index: index }));

  if (!items.length) {
    box.innerHTML = `<div class="empty-row">当前还没有可预览的原片，请先加入素材。</div>`;
    return [];
  }

  box.innerHTML = items
    .map(
      (source, index) => `<button class="draft-item source-item ${index === 0 ? "active" : ""}" data-index="${index}">
        <strong>${escapeHtml(source.label || source.file || `原始素材 ${index + 1}`)}</strong>
        <span>${escapeHtml(source.virtual_start && source.virtual_end ? `${source.virtual_start} - ${source.virtual_end}` : source.file || "原片")}</span>
      </button>`
    )
    .join("");

  document.querySelectorAll(".source-item").forEach((item) => {
    item.addEventListener("click", () => playSourceItem(items[Number(item.dataset.index)]));
  });

  return items;
}
```

## 6.12 修改 `playSourceVideo()`：sourceBasket 优先，默认播放最后加入的素材

当前 `playSourceVideo()` 已经有 sourceBasket 优先逻辑，但建议更明确：

```js
async function playSourceVideo(options = {}) {
  const { preferredIndex = null } = options;

  setPreviewMode("source");

  if (state.sourceBasket.length) {
    const sources = state.sourceBasket.map(sourceBasketPreviewItem);
    const previewItems = renderSourceVideoList(sources);
    const index = Number.isInteger(preferredIndex) ? preferredIndex : previewItems.length - 1;
    playSourceItem(previewItems[index] || previewItems[0]);
    return;
  }

  if (state.selectedTask) {
    await loadSourceVideos(state.selectedTask);
    return;
  }

  if (state.selectedRemoteVideo) {
    const url =
      state.selectedRemoteVideo.preview_url ||
      state.selectedRemoteVideo.media_low_url ||
      state.selectedRemoteVideo.mediaLow ||
      state.selectedRemoteVideo.media_high_url ||
      state.selectedRemoteVideo.mediaHigh;

    renderSourceVideoList([
      {
        label: state.selectedRemoteVideo.display_name || state.selectedRemoteVideo.name || "远程素材",
        file: state.selectedRemoteVideo.name || state.selectedRemoteVideo.remote_id || "",
        url,
        source_index: 1,
      },
    ]);
    if (url) {
      playSourceItem({
        label: state.selectedRemoteVideo.display_name || state.selectedRemoteVideo.name || "远程素材",
        file: state.selectedRemoteVideo.name || state.selectedRemoteVideo.remote_id || "",
        url,
        list_index: 0,
      });
    }
    return;
  }

  if (state.selectedVideo) {
    const item = {
      label: state.selectedVideo.name || state.selectedVideo.path,
      file: state.selectedVideo.path,
      url: `/api/videos/preview?path=${encodeURIComponent(state.selectedVideo.path)}`,
      list_index: 0,
    };
    renderSourceVideoList([item]);
    playSourceItem(item);
    return;
  }

  renderSourceVideoList([]);
  $("videoPreview").removeAttribute("src");
  $("fileViewer").textContent = "请先选择一个原片或任务。";
}
```

## 6.13 修改 `loadSourceVideos()`：任务原片列表加载失败时不要回退到成片空状态

当前：

```js
const sources = await api(`/api/tasks/${taskId}/source-videos`).catch(() => []);
if (state.previewMode !== "source") return;
if (!sources.length) {
  $("videoPreview").src = `/api/tasks/${taskId}/preview`;
  $("videoPreview").load();
  $("fileViewer").textContent = "正在预览原片。";
  return;
}
```

建议改成：

```js
async function loadSourceVideos(taskId) {
  const sources = await api(`/api/tasks/${taskId}/source-videos`).catch(() => []);
  if (state.previewMode !== "source") return;

  if (!sources.length) {
    renderSourceVideoList([]);
    try {
      $("videoPreview").src = `/api/tasks/${taskId}/preview`;
      $("videoPreview").load();
      $("fileViewer").textContent = "正在预览原片。";
    } catch (_) {
      $("fileViewer").textContent = "当前任务还没有可预览的原片，可能还在准备多源素材。";
    }
    return;
  }

  const previewItems = renderSourceVideoList(sources);
  playSourceItem(previewItems[0]);
}
```

## 九、结论

这个问题不是后端多源拼接逻辑错误，也不是 UCMS 视频数据错误，主要是前端状态管理混乱导致的：

```text
远程素材点击事件 = 加入素材篮 + 选中远程素材 + 清空任务面板 + 刷新任务列表
```

这几个动作混在一起，导致刚渲染出来的「原片列表」被后续刷新逻辑覆盖。

建议把交互职责拆清楚：

```text
点击远程素材：只加入 sourceBasket，并稳定展示 sourceBasket 的原片列表
点击原片 Tab：展示当前 sourceBasket 或任务原片
点击最新成片 Tab：展示 drafts
刷新任务/远程列表：不主动改变 previewMode
```

按以上方案修改后，`python run_web.py` 的启动方式不需要变，后端接口也基本不需要变，主要改 `web_static/app.js` 和 `web_static/index.html` 即可。

## 十、补充问题：任务队列子任务状态展示不合理

### 10.1 问题现象

当前左侧「任务队列」里，任务组下面的子任务卡片显示为：

```text
视频重组    14/14 · 失败 0
AI配音解说  0/1 · 失败 0
```

从用户视角看，这个展示有两个问题：

1. **“失败 0”没有表达任务状态**  
   用户真正关心的是这个子任务现在是“已完成 / 运行中 / 失败 / 排队中 / 未开始”，而不是失败数量。  
   `失败 0` 只能说明没有失败步骤，但不能说明任务是否完成。

2. **与主区域“运行状态：已完成”不一致**  
   主区域显示的是清晰状态：

```text
运行状态：已完成
```

但左侧任务队列子任务仍展示：

```text
14/14 · 失败 0
```

这会让用户误解：为什么已经完成了，左边还在强调“失败 0”？看起来像一个异常状态。

---

### 10.2 当前代码原因

`web_static/app.js` 的 `loadTasks()` 中，任务子项目前是这样渲染的：

```js
child.innerHTML = `
  <span class="task-child-mode">${escapeHtml(modeTitle)}</span>
  <span class="task-child-status">${task.done_steps}/${task.step_count} · 失败 ${task.failed_steps}</span>
  ${childBadge}
`;
```

也就是说，子任务状态区固定使用：

```text
完成步数 / 总步数 · 失败 N
```

这个写法偏开发调试视角，不适合普通工作台展示。

目前虽然有 `job_status`，但它只覆盖 `pending / running` 这种正在运行的情况：

```js
const childBadge = task.job_status
  ? `<em class="task-job-badge ${escapeAttr(task.job_status)}">${escapeHtml(jobStatusLabel(task.job_status))}</em>`
  : "";
```

如果任务已经结束，`job_status` 为空，就只能看到 `14/14 · 失败 0`。

---

### 10.3 优化目标

任务队列子任务应该优先展示“人能看懂的状态”，而不是失败计数。

推荐展示规则：

```text
已完成：     成功
失败：       失败
运行中：     进行中
排队中：     排队中
未开始：     未开始
部分完成：   进行中 / 未完成
```

子任务右侧可以展示为：

```text
视频重组      成功
AI配音解说    未开始
视频重组      进行中
AI配音解说    失败
```

如果还想保留步数，可弱化成辅助信息，例如：

```text
成功 · 14/14
失败 · 13/14
进行中 · 8/14
未开始 · 0/14
```

但不建议再把 `失败 0` 作为主展示。

## 十一、任务队列状态展示代码修改意见

### 11.1 新增子任务状态计算函数

在 `web_static/app.js` 中新增函数，建议放在 `preferredModeOrder()` 附近：

```js
function taskChildStatus(task) {
  const done = Number(task.done_steps || 0);
  const total = Number(task.step_count || 0);
  const failed = Number(task.failed_steps || 0);
  const jobStatus = task.job_status || "";

  if (jobStatus === "running") {
    return { label: "进行中", detail: `${done}/${total || "-"}`, className: "running" };
  }

  if (jobStatus === "pending") {
    return { label: "排队中", detail: `${done}/${total || "-"}`, className: "pending" };
  }

  if (jobStatus === "cancelled") {
    return { label: "已取消", detail: `${done}/${total || "-"}`, className: "cancelled" };
  }

  if (failed > 0) {
    return { label: "失败", detail: `${done}/${total || "-"}`, className: "failed" };
  }

  if (total > 0 && done >= total) {
    return { label: "成功", detail: `${done}/${total}`, className: "success" };
  }

  if (done > 0) {
    return { label: "进行中", detail: `${done}/${total || "-"}`, className: "running" };
  }

  return { label: "未开始", detail: total ? `${done}/${total}` : "等待启动", className: "pending" };
}
```

说明：

- `job_status` 优先级最高，用来识别“进行中 / 排队中 / 已取消”。
- 其次看 `failed_steps`，只要失败数大于 0，就显示“失败”。
- 再看 `done_steps >= step_count`，显示“成功”。
- `0/1 · 失败 0` 这类任务显示为“未开始”，而不是“失败 0”。

---

### 11.2 修改 `loadTasks()` 里的子任务 HTML

找到当前代码：

```js
const childBadge = task.job_status
  ? `<em class="task-job-badge ${escapeAttr(task.job_status)}">${escapeHtml(jobStatusLabel(task.job_status))}</em>`
  : "";
const modeTitle = task.mode_title || productionModeName(task.production_mode);

child.innerHTML = `
  <span class="task-child-mode">${escapeHtml(modeTitle)}</span>
  <span class="task-child-status">${task.done_steps}/${task.step_count} · 失败 ${task.failed_steps}</span>
  ${childBadge}
`;
```

替换为：

```js
const modeTitle = task.mode_title || productionModeName(task.production_mode);
const status = taskChildStatus(task);

child.innerHTML = `
  <span class="task-child-mode">${escapeHtml(modeTitle)}</span>
  <span class="task-child-status ${escapeAttr(status.className)}">
    ${escapeHtml(status.label)} · ${escapeHtml(status.detail)}
  </span>
`;
```

这样展示会从：

```text
视频重组    14/14 · 失败 0
```

变成：

```text
视频重组    成功 · 14/14
```

从：

```text
AI配音解说  0/1 · 失败 0
```

变成：

```text
AI配音解说  未开始 · 0/1
```

---

### 11.3 如果想更简洁：只展示中文状态

如果任务队列空间很小，推荐更简洁的版本：

```js
child.innerHTML = `
  <span class="task-child-mode">${escapeHtml(modeTitle)}</span>
```

这比 `失败 0` 更符合工作台用户的理解。

## 十三、补充结论

任务队列当前的 `14/14 · 失败 0`、`0/1 · 失败 0` 是开发视角的统计信息，不适合作为用户主状态。

建议把任务队列子任务状态改成：

```text

```
