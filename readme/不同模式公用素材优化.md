下面只针对这一件事写：**同一批数据源下，AI 配音解说任务与视频重组任务如何正确分组、复用公共分析，并修复“从已有任务切换模式时找不到源视频”的问题。**

# 多模式同源复用优化方案

## 1. 优化目标

当前系统已经有三个设计：

```text
1. 多源任务有 source_request.json
2. 同一批素材有 common_source_key / common_task_id
3. 前半段公共步骤可复用 COMMON_REUSABLE_STEPS
```

但缺少一个关键桥接逻辑：

```text
从已有任务切换生产模式时：
不能只依赖 manifest.source_video
应该优先复用旧任务 input/source_request.json 里的 source_items
```

最终要实现的效果是：

```text
同一批素材
  ├─ 公共分析 common_xxx
  │   ├─ metadata
  │   ├─ audio_extract
  │   ├─ frame_extract
  │   ├─ chunk_build
  │   ├─ asr
  │   ├─ vision
  │   ├─ timeline
  │   └─ timeline_digest
  │
  ├─ AI配音解说任务
  │   ├─ content_analysis
  │   ├─ short_video_edit_plan
  │   ├─ voiceover_script
  │   ├─ tts
  │   ├─ subtitles
  │   ├─ cut_plan
  │   └─ render
  │
  └─ 视频重组任务
      ├─ video_understanding
      ├─ highlight_detection
      ├─ highlight_reassembly_plan
      ├─ reassembly_cut_plan
      └─ reassembly_render
```

# 2. 当前问题原因

## 2.1 当前正常路径

用户从“本次剪辑素材”里加入多个远程素材，然后启动任务时，Web 后端会走：

```python
raw_source_items = _collect_source_items(req)
```

如果 `raw_source_items` 大于 1，就会写入：

```text
outputs/<task_id>/input/source_request.json
```

里面保存：

```json
{
  "task_id": "...",
  "production_mode": "ai_voiceover",
  "common_source_key": "...",
  "common_task_id": "common_xxx",
  "source_items": [...]
}
```

然后后端调用：

```bash
python run_multisource_pipeline.py --source-request outputs/<task_id>/input/source_request.json
```

`run_multisource_pipeline.py` 会：

```text
1. 根据 source_items 准备源素材
2. 生成 common_source_key
3. 跑公共分析
4. 把公共分析复制 / 同步到子任务
5. 再跑当前 production_mode 的后半段专属步骤
```

这条路径是对的。

---

## 2.2 出错路径

问题发生在：

```text
用户选中一个已有 AI 配音解说任务
然后把生产模式切成“视频重组”
再点击开始分析
```

这时前端通常只传：

```json
{
  "task_id": "xxx_AI配音解说_xxx",
  "production_mode": "highlight_reassembly"
}
```

后端进入：

```python
_prepare_mode_switched_run(req)
```

当前逻辑大概是：

```python
req.input_video = str(_existing_task_source_video(task_dir, manifest))
req.task_id = _with_mode_suffix(source_task_id, req.production_mode)
req.reuse_from_task_id = source_task_id
```

这里有致命问题：

```text
多源 virtual 模式没有 manifest.source_video
```

因为多源任务现在使用的是：

```json
{
  "source_mode": "multi_source_virtual",
  "source_video": "",
  "source_videos": [...]
}
```

所以 `_existing_task_source_video()` 会报：

```text
existing task source video missing
```

但实际上源素材并没有丢，它还在：

```text
outputs/<task_id>/input/source_request.json
```

因此修复重点是：

```text
切换模式时，优先从 source_request.json 继承 source_items
而不是强行从 manifest.source_video 找单个实体视频
```

# 4. web_app.py 详细修改方案

## 4.1 新增辅助函数：读取旧任务 source_request

在 `web_app.py` 中，建议放在 `_source_request_preview_items()` 附近，或者放在 `_prepare_mode_switched_run()` 上方。

新增：

```python
def _existing_task_source_request(task_dir: Path) -> dict[str, Any]:
    """
    Read source_request.json from an existing task.

    Multi-source tasks may not have manifest.source_video, especially when
    source_mode is multi_source_virtual. In that case, source_request.json is
    the source of truth for rebuilding another production mode task.
    """
    request_path = task_dir / "input" / "source_request.json"
    if not request_path.exists() or not request_path.is_file():
        return {}

    data = read_json(request_path, {})
    return data if isinstance(data, dict) else {}
```

作用：

```text
从已有任务目录里安全读取 input/source_request.json
没有就返回空 dict
避免后面到处写重复判断
```

---

## 4.2 新增辅助函数：判断 source_request 是否有效

继续新增：

```python
def _valid_source_request_items(source_request: dict[str, Any]) -> list[dict[str, Any]]:
    """
    Return valid source_items from a saved source_request.json.
    """
    items = source_request.get("source_items") or []
    if not isinstance(items, list):
        return []

    valid_items: list[dict[str, Any]] = []
    for item in items:
        if isinstance(item, dict):
            valid_items.append(item)

    return valid_items
```

作用：

```text
保证 source_items 是 list[dict]
避免老数据、坏数据导致后续异常
```

---

## 4.3 替换 `_prepare_mode_switched_run`

找到当前的：

```python
def _prepare_mode_switched_run(req: RunRequest) -> None:
    ...
```

替换为下面这个版本：

```python
def _prepare_mode_switched_run(req: RunRequest) -> None:
    """
    Prepare a run when the user switches production mode from an existing task.

    Example:
    - Existing task: AI voiceover
    - New selected mode: highlight reassembly

    Important:
    Multi-source virtual tasks do not necessarily have manifest.source_video.
    Their real source definition is input/source_request.json.
    Therefore, when switching mode, always prefer source_request.source_items.
    """
    # If user already submitted explicit sources, do not infer from old task.
    if _collect_source_items(req) or req.rerun or req.rerun_from or not req.task_id:
        return

    source_task_id = req.task_id.strip()
    if not source_task_id:
        return

    source_task_dir = _task_dir(source_task_id)
    source_manifest = read_json(source_task_dir / "manifest.json", {})

    current_mode = _task_id_production_mode(source_task_id) or _manifest_production_mode(source_manifest)
    if current_mode == req.production_mode:
        return

    # ------------------------------------------------------------------
    # Fix: multi-source mode switch should inherit source_items.
    # ------------------------------------------------------------------
    source_request = _existing_task_source_request(source_task_dir)
    source_items = _valid_source_request_items(source_request)

    if source_items:
        req.source_items = source_items

        # Clear single-source fields so /api/run will enter multi-source path.
        req.input_video = None
        req.input_videos = []
        req.remote_video = None
        req.remote_videos = []

        # Keep source-level options from the old task if available.
        # These options are part of common_source_key, so keeping them allows
        # the new mode task to reuse the same common analysis directory.
        if source_request.get("aspect_ratio"):
            req.aspect_ratio = str(source_request.get("aspect_ratio"))
        if source_request.get("chunk_seconds"):
            req.chunk_seconds = int(source_request.get("chunk_seconds"))
        if source_request.get("frame_interval"):
            req.frame_interval = int(source_request.get("frame_interval"))
        if source_request.get("mode"):
            req.mode = str(source_request.get("mode"))

        req.force_remote_download = bool(source_request.get("force_remote_download", req.force_remote_download))

        # Create the new task as the target production mode.
        req.task_id = _with_mode_suffix(source_task_id, req.production_mode)
        req.reuse_from_task_id = source_task_id
        return

    # ------------------------------------------------------------------
    # Fallback: single-source task mode switch.
    # ------------------------------------------------------------------
    req.input_video = str(_existing_task_source_video(source_task_dir, source_manifest))
    req.task_id = _with_mode_suffix(source_task_id, req.production_mode)
    req.reuse_from_task_id = source_task_id
```

这个版本解决两个问题：

```text
1. 多源任务切换模式时，不再要求 manifest.source_video 存在
2. 新模式任务会重新走 source_items 路径，从而重新计算 common_source_key 并复用公共分析
```

# 5. 关键逻辑说明

## 5.1 为什么要清空 input_video / remote_video？

因为 `/api/run` 里会根据：

```python
raw_source_items = _collect_source_items(req)
```

判断是单源还是多源。

`_collect_source_items()` 的逻辑是：

```python
if req.source_items:
    return req.source_items
```

所以只要我们给了：

```python
req.source_items = source_items
```

后续就会走多源路径。

但为了避免混乱，最好主动清空：

```python
req.input_video = None
req.input_videos = []
req.remote_video = None
req.remote_videos = []
```

这样可以保证新任务不会被误判为单源任务。

---

## 5.2 为什么要继承 aspect_ratio / chunk_seconds / frame_interval / mode？

因为 `_common_source_key()` 是按这些字段生成的：

```text
sources
aspect_ratio
chunk_seconds
frame_interval
mode
```

如果你从旧任务切换到新模式时，前端控件默认值和旧任务不同，就会导致：

```text
同一批素材，却生成了不同 common_source_key
```

结果就是无法复用公共分析。

所以从旧任务的 `source_request.json` 里继承这些字段，可以保证：

```text
AI 配音解说任务
视频重组任务
```

使用同一个：

```text
common_xxx
```

---

## 5.3 为什么不把 production_mode 放进 common_source_key？

不能放。

公共分析本来就是两个模式共享的：

```text
metadata
audio_extract
frame_extract
chunk_build
asr
vision
timeline
timeline_digest
```

这些步骤和 `production_mode` 没有关系。

如果把 `production_mode` 放进去，就会变成：

```text
AI配音解说 common_A
视频重组 common_B
```

这样公共分析无法复用，会重复跑 ASR、视觉理解、时间线融合，浪费大量时间。

所以正确做法是：

```text
common_source_key 不包含 production_mode
普通 task fingerprint 可以包含 production_mode
```

你的代码现在就是这个方向，不要改错。

# 6. 兼容单源任务

上面的修复不会破坏单源任务。

因为单源任务一般没有：

```text
input/source_request.json
```

所以：

```python
source_items = _valid_source_request_items(source_request)
```

会返回空列表，然后继续走旧逻辑：

```python
req.input_video = str(_existing_task_source_video(source_task_dir, source_manifest))
```

也就是说：

```text
单源视频：继续用 manifest.source_video
多源视频：优先用 source_request.source_items
```

这个分支是合理的。

# 12. 最小改动版代码

如果你想让 Codex 快速改，只给它这个任务即可：

```text
修改 web_app.py：

1. 新增 _existing_task_source_request(task_dir)
2. 新增 _valid_source_request_items(source_request)
3. 替换 _prepare_mode_switched_run(req)

目标：
当用户从已有任务切换 production_mode 时，若旧任务 input/source_request.json 存在且包含 source_items，则用这些 source_items 创建新模式任务，不要调用 _existing_task_source_video。
```
