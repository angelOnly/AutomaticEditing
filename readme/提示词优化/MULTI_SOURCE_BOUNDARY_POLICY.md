# 多源素材边界与跨源编排规则

## 一、适用范围

本规则只嵌入最终编排类 prompt：

1. `SHORT_VIDEO_EDIT_PLAN_TEXT_PROMPT`
2. `HIGHLIGHT_REASSEMBLY_TEXT_PROMPT`

本规则不用于：

1. ASR 摘要。
2. 视觉分析。
3. 整体视频理解。
4. 候选片段检测。
5. 配音文案生成。

原因是：多源边界判断只应该影响最终 `clip_ids` 的选择和排序，不应该要求前置分析步骤输出额外字段。

## 二、输入字段说明

### `source_id`

含义：候选 clip 所属的原始素材源。

来源：代码根据多源素材清单和 chunk 时间轴补全。

用途：帮助模型判断不同 clip 是否来自同一条原始视频。

下游是否使用：模型不输出该字段，下游由代码继续保留。

### `clip_id`

含义：候选 clip 的唯一编号。

来源：代码生成。

用途：模型只能通过 `clip_ids` 选择和排序片段。

下游是否使用：是。代码根据 `clip_ids` 回填时间码、source_id、时长和剪辑结构。

### `summary / speech / visual / type`

含义：候选 clip 的摘要、声音内容、画面内容和候选类型。

来源：前置模型输出和代码 materialize。

用途：判断跨源组合是否有新闻逻辑。

下游是否使用：模型不输出这些字段，只用于判断。

## 三、核心原则

`source_id` 不同，不代表不能组合。

但 `source_id` 不同意味着：

1. 它们不是同一条原始视频的连续镜头。
2. 它们不是同一现场机位的自然切换。
3. 它们不是同一句话、同一段采访或同一个现场声的天然延续。

模型只能在选择 `clip_ids` 和排列顺序时使用这些信息。

模型不得输出：

1. `source_id`
2. `source_start`
3. `source_end`
4. `start`
5. `end`
6. `duration_seconds`
7. `transition_after`
8. `excluded_clip_ids`

这些字段全部由代码根据 `clip_ids` 自动回填。

## 四、允许跨源组合的情况

只有满足以下任一条件，才可以把不同 `source_id` 的 clip 放进同一条成片：

1. 它们属于同一新闻事件的不同阶段。
2. 一个 clip 提供背景，另一个 clip 提供现场证据。
3. 一个 clip 提供人物或机构表态，另一个 clip 提供相关画面、反应或后续进展。
4. 多个 clip 共同回答同一个核心问题，例如“发生了什么”“为什么重要”“目前进展如何”。
5. 多个 clip 之间存在清楚的时间、因果、对照或信息递进关系。
6. 跨源组合能让观众更清楚，而不是制造理解负担。

## 五、不允许跨源组合的情况

以下情况不要跨源组合：

1. 只是因为画面好看，但主题并不一致。
2. 前后 clip 语境不同，组合后会造成断章取义。
3. 前一个 source 是半句话，后一个 source 无法自然承接。
4. 一个 source 是资料画面，另一个 source 是现场画面，组合后会让观众误以为资料画面就是事件现场。
5. 多个 source 重复表达同一背景，没有新增信息。
6. 跨源后需要大量解释才能让观众明白。
7. 不同 source 分属不同新闻事件、不同人物阶段或不同历史节点，且没有明确共同主题。

## 六、排序原则

跨源组合时，不要机械按照 `source_id` 排序。

优先按新闻叙事关系排序：

1. 背景交代。
2. 事件现场或关键画面。
3. 关键人物或机构表态。
4. 影响、结果或后续进展。
5. 当前状态或后续关注点。

如果时间顺序、因果关系或新闻理解需要，可以调整 clip 顺序。

但调整顺序不能制造“同一现场连续发生”的错觉。

## 七、多条输出时的去重原则

如果允许输出多条视频：

1. 不要让每条视频都重复使用同一个开头 clip。
2. 不要让多个视频重复讲同一个事实。
3. 优先按不同新闻角度、事件阶段、人物表态或现场进展拆分。
4. 如果多个候选都属于同一事件链，优先合成一条完整视频，不要拆碎。

## 八、嵌入到 prompt 时的推荐写法

```text
多源素材边界与跨源编排规则：
1. source_id 不同的 clip 可以组合，但必须服务同一新闻主题、事件链、因果关系、对照关系或信息递进。
2. source_id 不同的 clip 不是同一原始视频的连续镜头，不要把跨源衔接当作同一现场、同一机位或同一句话的自然延续。
3. 允许跨源的情况：背景加现场、表态加证据、事件阶段递进、共同回答同一个核心问题。
4. 禁止跨源的情况：主题不一致、语境断裂、半句话拼接、资料画面被误当现场、重复同一背景、需要大量解释才能理解。
5. 排序优先按新闻叙事关系：背景、现场、表态、影响或结果、当前状态。
6. 多条输出时避免重复使用同一个开头 clip，也不要重复讲同一个事实。
7. 本规则只影响 clip_ids 的选择和排序，不要求输出任何额外字段。
```

## 九、最终输出约束

最终输出仍按当前任务 schema 输出。

AI 配音规划只输出：

```json
{
  "videos": [
    {
      "clip_ids": [],
      "讲述重点": "",
      "必须讲到": []
    }
  ]
}
```

原声重组规划只输出：

```json
{
  "videos": [
    {
      "clip_ids": []
    }
  ]
}
```
