你现在这个 `SHORT_VIDEO_EDIT_PLAN_TEXT_PROMPT` 最大问题是：**它只在做“剪辑清单规划”，没有在做“短视频叙事规划”**。

AI 配音解说不是简单把几个高光片段串起来，然后让模型写一段旁白。真正吸引人的新闻解说，核心是：

> 先让观众产生“我为什么要继续看”的理由，再用清楚的故事线把信息讲完，最后给一个判断、反差或余味。

所以提示词不能只问模型：
“选哪些片段？按什么顺序？”
还应该问模型：
“这条短视频要怎么讲？观众为什么会被吸引？开头钩子是什么？冲突是什么？中段怎么递进？结尾落在哪？”

---

## 一、吸引人的新闻解说，应该具备什么特点？

### 1. 开头不是交代背景，而是先抛出“问题 / 冲突 / 反常识”

很多新闻解说不好看，是因为一上来就这样：

> 近日，某地发生一起事件。据了解，事情发生在……

这是传统新闻稿写法，不适合短视频。

短视频 AI 解说更适合这样开头：

> “一场看似普通的发布会，最后却变成了外交交锋。”
> “这段画面最关键的地方，不是他说了什么，而是旁边人的反应。”
> “为什么一个只有几十秒的现场，会迅速引发外界关注？”

好开头通常有几种类型：

| 类型    | 适合场景        | 示例                         |
| ----- | ----------- | -------------------------- |
| 悬念型   | 事件有后续、有反转   | “这件事最值得注意的，不是结果，而是它释放的信号。” |
| 冲突型   | 双方对立、现场交锋   | “表面上是一次回应，实际上是一次强硬表态。”     |
| 反差型   | 画面和事实不一致    | “画面看起来很平静，但背后的信息量并不小。”     |
| 结果前置型 | 先说影响        | “这次表态，可能会影响接下来几周的局势走向。”    |
| 细节放大型 | 画面里有关键动作/话语 | “注意这个停顿，它其实比完整发言更有信息量。”    |

也就是说，AI 配音短视频的第一句话，不应该是“新闻背景”，而应该是**观看理由**。

---

### 2. 文案要围绕一个“核心看点”，不能什么都讲

新闻素材里可能有很多信息，但短视频不能像长新闻一样面面俱到。

一条 AI 配音视频最好只讲一个核心问题：

> 这件事为什么重要？
> 这个现场发生了什么变化？
> 这个人物的表态意味着什么？
> 这个事件背后有什么信号？
> 这段画面最值得注意的细节是什么？

比如同一个新闻素材，不能同时讲：

* 谁出席了会议
* 双方说了什么
* 历史背景是什么
* 国际反应如何
* 未来走势如何
* 现场画面有什么细节

这样会散。

更好的方式是只抓一个角度：

> “这不是一次普通会面，而是一次信号释放。”
> “这场冲突的关键，不在现场，而在后续反应。”
> “这段画面真正值得看的是：双方态度已经发生变化。”

所以你的规划 prompt 里应该要求模型输出：

```json
"core_story_question": "这条短视频主要回答什么问题？",
"main_viewpoint": "这条视频最终想让观众理解什么？",
"audience_hook": "观众为什么要继续看？"
```

否则后面的 `voiceover_script` 很容易写成流水账。

---

### 3. 解说要有“递进”，不是平铺事实

好的新闻解说一般是这个结构：

```text
钩子 → 发生了什么 → 为什么重要 → 关键细节 → 影响/判断
```

或者：

```text
异常点 → 现场事实 → 背后原因 → 可能影响 → 总结落点
```

它不是简单的：

```text
片段1发生了A
片段2发生了B
片段3发生了C
```

而是要让观众感觉信息在不断升级：

第一层：发生了什么。
第二层：为什么这个事情值得看。
第三层：背后反映了什么。
第四层：接下来可能影响什么。

比如：

> “这段现场之所以引发关注，是因为它释放了一个很明确的信号。第一，发言人的措辞比之前更直接。第二，现场回应没有留下太多回旋空间。第三，相关方后续动作可能会进一步升级。所以这不是一次孤立表态，而是局势变化中的一个节点。”

这种就有递进。

你的规划 prompt 应该要求每条短视频输出：

```json
"narrative_arc": {
  "opening_hook": "",
  "setup": "",
  "turning_point": "",
  "key_evidence": "",
  "ending_point": ""
}
```

这样 `voiceover_script` 才有故事骨架。

---

### 4. 文案要“解读画面”，不能只复述画面

AI 配音模式最大的价值不是把画面内容念一遍。

差的解说：

> “画面中可以看到，现场有很多人，发言人正在讲话。”

好的解说：

> “注意现场的反应。发言人这句话说完后，镜头没有马上切走，而是停在了对方代表的表情上，这让这段话的态度更明显。”

也就是说，AI 解说应该完成三件事：

1. 告诉观众画面里发生了什么。
2. 告诉观众这个画面为什么重要。
3. 告诉观众它和整个新闻事件有什么关系。

因此，规划阶段不要只输出：

```json
"visual": "",
"fact": ""
```

应该增加：

```json
"why_this_shot_matters": "",
"voiceover_role": "hook/setup/evidence/transition/climax/ending"
```

每个镜头不是随便放的，它要承担叙事功能。

---

### 5. 语言要口语化，但不能低俗、夸张、标题党

新闻短视频要吸引人，但不能写成营销号。

不建议：

> “惊天大反转！”
> “彻底炸锅了！”
> “全球都没想到！”
> “这下麻烦大了！”

更适合：

> “这句话的分量不轻。”
> “这背后其实有一个关键变化。”
> “真正值得注意的，是接下来会发生什么。”
> “表面上看是回应，实际上是在划线。”

新闻 AI 解说适合的语气是：

* 清楚
* 有判断
* 有节奏
* 不装腔
* 不煽动
* 不乱下结论
* 不过度预测

可以理解为：

> 像一个懂新闻的人，在帮观众把复杂信息讲清楚，而不是像一个营销号在制造情绪。

---

### 6. 每句话都要短，适合配音和字幕

AI 配音文案不能写长句。

差的句子：

> “此次事件之所以受到外界高度关注，是因为它不仅涉及地区局势的持续变化，也反映出相关各方在外交、军事和舆论层面上的复杂博弈。”

太长，不适合配音。

更好：

> “这件事之所以受到关注，不只是因为现场本身。
> 更重要的是，它反映出相关各方的态度正在变化。
> 外交表态、军事动作和舆论反应，正在互相影响。”

也就是说，后续 `voiceover_script` 应该遵守：

* 一句尽量 8 到 20 个汉字。
* 少用长定语。
* 少用“由于、因此、与此同时、进一步表明”这种书面连接。
* 多用短节奏：

  * “但问题在于……”
  * “真正关键的是……”
  * “这释放了一个信号……”
  * “接下来要看两点……”

---

## 二、AI 新闻解说最推荐的几种结构

你可以让模型根据素材选择结构，而不是固定一种。

### 结构 A：事件解释型

适合普通新闻事件。

```text
1. 开头抛问题：这件事为什么引发关注？
2. 简述发生了什么。
3. 解释关键背景。
4. 点出核心变化。
5. 给出影响或后续观察点。
```

适合：

* 政治新闻
* 国际新闻
* 社会事件
* 发布会
* 外交回应

---

### 结构 B：现场细节型

适合画面信息强的素材。

```text
1. 先提示观众注意某个画面细节。
2. 解释这个细节发生在什么场景。
3. 说明它为什么不寻常。
4. 引出事件背后的信号。
5. 结尾回到这个细节的意义。
```

适合：

* 会议现场
* 记者会交锋
* 突发现场
* 人物表情、动作、停顿明显的视频

---

### 结构 C：冲突升级型

适合双方对立明显的新闻。

```text
1. 开头指出冲突焦点。
2. 交代双方各自说法。
3. 展示冲突升级的节点。
4. 分析为什么升级。
5. 结尾说明后续风险。
```

适合：

* 国际冲突
* 舆论争议
* 政策对抗
* 地区局势

---

### 结构 D：反差反转型

适合有“表面 vs 实际”的新闻。

```text
1. 表面看起来是一个普通事件。
2. 但其中有一个反常细节。
3. 解释这个细节背后的含义。
4. 补充事实证据。
5. 给出真正看点。
```

适合：

* 看似普通但含义重大的外交新闻
* 官方表态
* 会议安排
* 人物出场顺序
* 措辞变化

---

## 三、现在这个 prompt 的核心缺陷

你现在的输出是：

```json
{
  "topic": "",
  "news_angle": "",
  "title": "",
  "target_duration_seconds": 55,
  "source_clip_ids": [],
  "must_keep_fact_points": [],
  "editing_structure": []
}
```

这个结构可以做剪辑，但不够支撑好文案。

它缺少：

1. **开头钩子**
   后面的文案模型不知道第一句话怎么抓人。

2. **核心问题**
   不知道这条视频到底回答什么。

3. **叙事结构**
   只知道镜头顺序，不知道信息怎么递进。

4. **观点落点**
   不知道结尾应该收在哪里。

5. **镜头作用**
   每个片段为什么要用？是用来铺垫、证明、转折，还是结尾？

6. **观众视角**
   没有判断普通观众为什么会看这条视频。

7. **配音风格约束**
   没有提前规定“新闻解说口吻”，容易变成新闻稿或营销号。

所以这个 prompt 应该从“短视频编辑规划”升级成：

> **AI 配音短视频叙事与剪辑规划 prompt**

例如：

* `opening_hook`
* `setup`
* `evidence`
* `transition`

这样后面的配音文案就不会乱写。

## 五、优化后的 Prompt 草案

下面是我建议你替换的新版提示词，偏工程可落地。

禁止把同一新闻的前因、现场、后续反应拆成不同视频。

====================
二、什么样的AI新闻解说更吸引人
====================

AI配音新闻短视频不是新闻稿朗读，也不是画面复述。

一条好的新闻解说应具备：

1. 开头有钩子
   - 先告诉观众为什么要看。
   - 可以使用悬念、冲突、反差、关键细节、结果前置等方式。
   - 不要一上来写“近日”“据了解”“画面显示”这类平铺开头。

2. 只有一个核心看点
   - 每条视频只回答一个主要问题。
   - 不要把所有背景都塞进去。
   - 不要把多个新闻角度混在一起讲散。

3. 叙事有递进
   - 不是简单罗列片段。
   - 应该形成：钩子 → 发生了什么 → 为什么重要 → 关键证据/细节 → 影响或结论。
   - 信息要一层一层推进。

4. 解说要解释画面
   - 不要只说“画面中可以看到”。
   - 要说明这个画面为什么重要。
   - 要把画面、事实和新闻意义连接起来。

5. 语言适合AI配音
   - 句子短。
   - 节奏清楚。
   - 口语化但不低俗。
   - 有判断但不武断。
   - 不使用夸张标题党表达。

6. 保持新闻专业性
   - 不夸大事实。
   - 不编造背景。
   - 不做没有依据的预测。
   - 不使用“惊天”“炸裂”“彻底翻车”“全球震惊”等营销号语言。

====================
三、可选叙事类型
====================

请为每条短视频选择一种最合适的 story_type：

1. event_explainer
   事件解释型。
   适合普通新闻事件。
   结构：发生了什么 → 为什么重要 → 关键背景 → 影响。

2. detail_focus
   现场细节型。
   适合画面里有关键动作、表情、停顿、发言、现场反应的素材。
   结构：注意一个细节 → 解释现场 → 说明细节意义 → 回到事件影响。

3. conflict_escalation
   冲突升级型。
   适合双方对立、外交交锋、争议事件、局势升级。
   结构：冲突焦点 → 双方动作/说法 → 升级节点 → 后续风险。

4. contrast_reveal
   反差揭示型。
   适合“表面普通，但背后有信号”的素材。
   结构：表面现象 → 反常细节 → 背后含义 → 真正看点。

如果不确定，优先选择 event_explainer。

====================

只能使用输入候选片段中的时间码。

- k = 0 的片段；
- u = "drop" 的片段；
- 无法独立支撑新闻事实的片段；
- 只有空泛画面、没有新闻信息量的片段；
- 与主线无关的片段。

AI 配音模式优先选择：
- u = "av"
- u = "both"

可以选择 u = "voiceover" 或其他适合配音覆盖的片段，但必须说明其画面价值。

不要为了凑时长选择低价值片段。

默认 recommended_video_count = 1。

- 事件现场；
- 当事人回应；

应尽量合并为一条完整视频，而不是拆开。

每条视频 target_duration_seconds 建议：

- 信息复杂且片段充足：60-90 秒。

不要机械固定为 55 秒。
请根据候选片段的信息密度和叙事完整度设置目标时长。

每条短视频必须包含以下叙事信息：

6. audience_hook
   观众为什么要继续看。
   例如：“现场措辞出现变化，可能释放新的政策信号。”

7. main_viewpoint
   这条视频最终要让观众理解的核心判断。
   必须基于输入事实，不得编造。

8. ending_takeaway
   结尾落点。
   可以是影响、后续观察点、事件意义，但不能做无依据预测。

9. narrative_arc
   叙事弧线，包括：
   - opening_hook：开头钩子
   - setup：事件基本信息
   - development：信息推进
   - turning_point：关键变化或转折
   - key_evidence：最关键的事实或画面证据
   - ending_point：结尾落点

10. editing_structure
   镜头结构。
   每个镜头必须说明：
   - 用哪个候选片段；
   - 使用哪段时间码；
   - 画面内容；
   - 对应事实；
   - 这个镜头在解说中的作用；
   - 为什么这个镜头值得保留；
   - 建议配音讲什么信息点。

====================
八、镜头角色定义
====================

editing_structure 中的 voiceover_role 只能使用以下值：

- opening_hook：开头钩子，用来吸引观众继续看。
- setup：交代事件基本信息。
- evidence：提供关键事实或画面证据。
- context：补充必要背景。
- transition：承接上下信息。
- climax：信息最强、冲突最明显、判断最关键的位置。
- ending：结尾总结或后续观察点。

每条视频必须至少包含：
- 1 个 opening_hook 或 setup；
- 1 个 evidence；
- 1 个 ending。

如果素材足够，建议包含 climax。

====================
九、输出要求
====================

只输出 JSON，不要输出解释文字。

输出格式如下：

## 六、还要同步优化 `voiceover_script`，否则规划再好也会浪费

这个 prompt 优化后，`short_video_edit_plan` 会输出更好的故事骨架。
但真正生成文案的是 `voiceover_script`，所以后面那个 prompt 也必须吃这些字段。

尤其要让 `voiceover_script` 使用：

```json
"core_story_question"
"audience_hook"
"main_viewpoint"
"ending_takeaway"
"narrative_arc"
"editing_structure[].voiceover_role"
"editing_structure[].suggested_voiceover_point"
```

否则这些字段只是摆设。

`voiceover_script` 应该被要求：

1. 第一秒必须用 `opening_hook`，不要新闻稿开头。
2. 每句话尽量短。
3. 一句话一行，便于字幕。
4. 按 `editing_structure` 的镜头顺序写。
5. 每段文案要对应画面，但不能只复述画面。
6. 不能编造事实。
7. 结尾用 `ending_takeaway` 收住，不要喊口号。

## 七、我建议你把 AI 配音新闻解说定义成这句话

可以作为系统内部标准：

> AI 配音新闻短视频，不是把新闻稿念短一点，而是用短视频节奏，把一个新闻事件讲成“有钩子、有递进、有解释、有落点”的一分钟新闻故事。

这句话很重要。

因为它能区分三种东西：

| 类型     | 特点               | 问题       |
| ------ | ---------------- | -------- |
| 新闻稿    | 正式、完整、平铺         | 短视频不吸引人  |
| 营销号    | 夸张、情绪化、标题党       | 不适合新闻专业性 |
| AI新闻解说 | 清楚、有节奏、有判断、有事实边界 | 最适合你的项目  |

你的系统应该追求第三种。
