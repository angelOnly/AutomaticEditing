你这个 `VOICEOVER_QUALITY_CHECK_PROMPT` 现在最大问题是：**它只检查事实合不合格，不检查“作为一条新闻短视频解说是否好看、能不能配音、能不能剪辑”。**

当前检查项只有：

```text
1. 是否覆盖 required facts
2. 是否过短
3. 是否编造事实
4. 是否结构完整
```

这太基础了。

它最多能防止文案“严重出错”，但不能保证文案：

* 开头有吸引力；
* 叙事有递进；
* 语言适合 AI 配音；
* 字幕好读；
* 和镜头结构匹配；
* 时长合理；
* 没有营销号口吻；
* 没有新闻风险；
* 能自然引导剪辑。

所以它应该从：

> fact checker

升级成：

> news voiceover script quality gate

也就是 **AI 配音新闻解说文案质量门禁**。

---

# 一、AI 配音文案到底应该检查什么？

我建议分成 8 个维度。

---

## 1. 事实完整性：该讲的事实有没有讲到

这是最基础的。

要检查：

```text
required facts 是否都覆盖？
must_keep_fact_points 是否都覆盖？
核心人物、时间、地点、事件、动作、结果是否缺失？
有没有漏掉导致观众看不懂的关键信息？
```

但注意，不是所有 fact 都必须逐字出现。

只要文案用自然语言准确表达了同一个事实，就算覆盖。

比如 required fact 是：

```text
发言人回应了记者关于地区局势的问题
```

文案写成：

```text
面对记者追问，发言人把重点放在地区局势的变化上。
```

这可以算覆盖。

---

## 2. 事实安全性：有没有编造、夸大、误导

这个非常重要。

要检查：

```text
有没有输入里没有的人名、机构、国家、数据？
有没有把“可能”说成“已经”？
有没有把“回应”说成“承认”？
有没有把“表态”说成“警告”？
有没有把“引发关注”说成“引爆全球”？
有没有无依据预测？
```

新闻解说可以有判断，但判断必须基于素材。

比如可以说：

```text
这释放出一个更强硬的信号。
```

但前提是输入里确实有措辞变化、现场反应或上下文支撑。

不应该说：

```text
这意味着局势即将失控。
```

除非素材明确给了这个判断依据。

---

## 3. 结构完整性：有没有形成新闻故事

AI 配音文案不是事实列表。

要检查它有没有一个完整的短视频结构：

```text
开头钩子
事件交代
关键事实
解释或递进
结尾落点
```

差的结构：

```text
某某发生了什么。
某某又说了什么。
现场还有什么。
事情还在继续。
```

好的结构：

```text
这件事真正值得注意的，是现场释放出的信号。
先看发生了什么。
接着看关键表态。
最后看它为什么可能影响后续局势。
```

质量检查应该判断：

```text
有没有开头？
有没有中段推进？
有没有结尾？
是不是只是流水账？
```

---

## 4. 开头吸引力：第一句话能不能留住观众

这是当前 prompt 完全没检查的。

短视频 AI 解说最关键的是前 3 秒。

要检查：

```text
第一句话是否有观看理由？
是否抛出了问题、冲突、反差或关键信号？
是否避免新闻稿开头？
```

不好的开头：

```text
近日，某地发生一起事件。
据了解，相关部门表示。
画面中可以看到。
```

更好的开头：

```text
这段现场最值得注意的，不是发言本身，而是措辞变化。
一次看似普通的回应，背后释放了新的信号。
这件事为什么会引发外界关注？关键在这几个细节。
```

质量检查里应该明确：

> 如果开头平铺直叙、没有钩子，可以不判严重失败，但应建议 rewrite。

---

## 5. 解说价值：有没有“解释画面”，而不是复述画面

AI 配音文案最常见的问题是：

```text
画面中可以看到……
现场出现了……
随后镜头切到……
```

这只是复述画面。

真正好的 AI 解说要做到：

```text
这个画面说明了什么？
这句话为什么重要？
这个动作和新闻主线有什么关系？
```

质量检查应该判断：

```text
文案有没有解释“为什么重要”？
有没有把画面和新闻意义连接起来？
有没有只是在描述画面？
```

如果文案只是画面说明书，就应该要求重写。

---

## 6. 语言风格：新闻化、口语化，但不能营销号

要检查语气。

合格风格：

```text
清楚
克制
有判断
短句
适合配音
有节奏
```

不合格风格：

```text
太像新闻通稿
太像营销号
太书面
太啰嗦
太空泛
太情绪化
```

应该禁止：

```text
震惊
炸裂
彻底翻车
全球都没想到
重磅猛料
惊天反转
全网沸腾
```

也要避免过度官方腔：

```text
在当前复杂严峻的形势下
有关方面高度重视
进一步彰显了重要意义
具有十分重要的现实意义
```

---

## 7. 配音可用性：句子能不能被 TTS 自然读出来

这个很关键。

TTS 不喜欢长句、复杂嵌套、标点混乱。

要检查：

```text
句子是否太长？
有没有一口气读不完的句子？
有没有过多书面连接词？
有没有适合字幕断句？
是否适合“一句话一行”？
```

建议标准：

```text
单句尽量 8-25 个汉字。
少数解释句可以稍长，但不要超过 35 个汉字。
每句话只表达一个意思。
```

不好的句子：

```text
这件事之所以引发广泛关注，是因为它不仅涉及相关各方在外交层面的持续博弈，也反映出当前地区局势在多个方向上都出现了更加复杂的变化。
```

更好的句子：

```text
这件事之所以引发关注，不只是因为现场本身。
更重要的是，它反映出相关各方的态度正在变化。
外交表态和地区局势，正在互相影响。
```

质量检查应该能判断：
**这段文案能不能直接送给 TTS。**

---

## 8. 剪辑适配性：文案和镜头能不能对上

AI 配音模式里，文案不是孤立的。

它后面要给：

```text
tts → cut_plan → render
```

所以要检查：

```text
文案顺序是否和 editing_structure 对得上？
开头文案是否适合放在强画面上？
讲到某个事实时，是否有对应镜头支撑？
有没有文案讲了画面没有的信息？
有没有画面很强，但文案没有利用？
```

尤其你的前面 `short_video_edit_plan` 已经有：

```json
"voiceover_role": "opening_hook",
"suggested_voiceover_point": ""
```

那质量检查就应该判断：

```text
voiceover 有没有遵守这些角色？
是否覆盖 suggested_voiceover_point？
是否和 narrative_arc 一致？
```

否则前面做的叙事规划就浪费了。

# 二、现在这个输出也太简单

当前输出：

```json
{
  "ok": 1,
  "rewrite": 0,
  "missing": []
}
```

问题是：

1. 不知道为什么不合格。
2. 不知道是哪一类问题。
3. 不知道是否需要局部修改还是整体重写。
4. 不知道文案哪里有风险。
5. 不知道 TTS 是否可用。
6. 不知道是否和剪辑规划匹配。
7. 后续 pipeline 很难根据结果自动处理。

建议升级成：

```json
{
  "ok": 1,
  "rewrite": 0,
  "severity": "pass",
  "scores": {
    "fact_coverage": 5,
    "factual_safety": 5,
    "structure": 4,
    "opening_hook": 4,
    "narrative_flow": 4,
    "voiceover_naturalness": 5,
    "subtitle_readability": 5,
    "edit_alignment": 4
  },
  "missing": [],
  "issues": [],
  "rewrite_instructions": []
}
```

如果你想兼容旧 pipeline，也可以保留 `ok/rewrite/missing`，新增字段不影响后续使用。

# 三、哪些问题应该判 `ok=0`？

不是所有问题都要阻断 TTS。

我建议分三档。

---

## A 类：严重问题，必须 `ok=0, rewrite=1`

这些不能进入 TTS：

```text
1. 编造关键事实。
2. 漏掉核心事实，导致新闻不成立。
3. 文案主题和 short_video_edit_plan 不一致。
4. 文案把多个事件混在一起，叙事混乱。
5. 文案明显太短，无法支撑目标视频。
6. 文案明显太长，远超目标时长。
7. 文案没有完整结构。
8. 文案有严重标题党、煽动或不专业表达。
9. 文案和镜头完全对不上。
```

---

## B 类：中等问题，`ok=1, rewrite=1`

这些可以进入后续，但建议重写或优化：

```text
1. 开头不够吸引人。
2. 有些句子太长。
3. 文案偏新闻稿。
4. 有少量重复。
5. 结尾比较弱。
6. 解释不够，有点像画面复述。
7. 节奏一般，但事实没问题。
```

这个很实用。

因为有时候你不想因为文案不够精彩就阻塞整个 pipeline，但可以标记：

```json
"rewrite": 1
```

后面如果你做自动重试，就可以触发改写。

---

## C 类：轻微问题，`ok=1, rewrite=0`

这些不用阻塞：

```text
1. 个别句子可以更顺。
2. 标题和文案风格不是特别强，但可用。
3. 结尾普通但不错误。
4. 信息完整，配音自然。
```

---

# 四、文案质量评分标准

我建议内部用 5 分制。

| 维度    | 5 分        | 3 分   | 1 分    |
| ----- | ---------- | ----- | ------ |
| 事实覆盖  | 必要事实完整     | 有小遗漏  | 漏掉核心事实 |
| 事实安全  | 无编造无夸大     | 有轻微推断 | 明显编造   |
| 结构完整  | 钩子、推进、结尾完整 | 有结构但平 | 流水账    |
| 开头吸引力 | 第一秒有看点     | 普通开头  | 新闻稿开头  |
| 叙事递进  | 信息逐层推进     | 基本顺序  | 杂乱跳跃   |
| 解说价值  | 能解释意义      | 部分复述  | 只描述画面  |
| 配音自然度 | 短句顺口       | 有长句   | 难读     |
| 字幕友好  | 一句一行清楚     | 部分过长  | 不适合字幕  |
| 剪辑匹配  | 和镜头强匹配     | 基本匹配  | 对不上    |

建议通过规则：

```text
严重事实错误：直接 ok=0
事实覆盖 < 3：ok=0
事实安全 < 4：ok=0
结构完整 < 3：ok=0
配音自然度 < 3：rewrite=1
开头吸引力 < 3：rewrite=1
剪辑匹配 < 3：rewrite=1 或 ok=0
```

# 五、建议新版输出格式

推荐这个：

```json
{
  "ok": 1,
  "rewrite": 0,
  "severity": "pass",
  "missing": [],
  "scores": {
    "fact_coverage": 5,
    "factual_safety": 5,
    "structure": 4,
    "opening_hook": 4,
    "narrative_flow": 4,
    "explanatory_value": 4,
    "voiceover_naturalness": 5,
    "subtitle_readability": 5,
    "edit_alignment": 4
  },
  "issues": [],
  "rewrite_instructions": [],
  "estimated_voiceover_seconds": 52,

}
```

字段说明：

```text
ok：
是否允许进入 TTS。

rewrite：
是否建议重写或优化。

pass / minor / major / critical。

missing：
缺失的 required fact 编号。

各维度 1-5 分。

发现的问题列表。

rewrite_instructions：
如果需要重写，给出改写方向。

estimated_voiceover_seconds：
估算配音时长。

duration_fit：
too_short / fit / too_long。
```

# 六、推荐新版 VOICEOVER_QUALITY_CHECK_PROMPT

可以改成这样：

```python
VOICEOVER_QUALITY_CHECK_PROMPT = r"""
你是一个资深新闻短视频 AI 配音文案质检编辑。

你的任务不是生成文案，而是检查已经生成好的 AI voiceover script 是否可以进入 TTS、cut_plan 和 render。

你需要判断这段文案是否：
1. 准确覆盖必要新闻事实；
2. 没有编造、夸大或误导；
3. 具备适合短视频的新闻解说结构；
4. 开头有吸引力；
5. 叙事有递进；
6. 能解释画面和新闻意义，而不是只复述画面；
7. 语言适合 AI 配音；
8. 字幕友好；
9. 能和短视频剪辑规划匹配。

====================
一、核心质量标准
====================

一条合格的 AI 配音新闻解说，不是新闻稿朗读，也不是营销号文案。

它应该是：

有钩子、有事实、有解释、有递进、有落点的短视频新闻解说。

基本结构应为：

开头钩子 → 事件交代 → 关键事实/画面证据 → 新闻意义解释 → 结尾落点

====================
二、必须检查的内容
====================

1. 事实覆盖

检查 voiceover 是否覆盖输入中的 required facts / must_keep_fact_points。

如果 required facts 有编号，请在 missing 中返回缺失的编号。

注意：
- 不要求逐字复述。
- 只要文案准确表达了同一事实，就算覆盖。
- 如果缺失事实会导致观众无法理解事件，应判为严重问题。

2. 事实安全

检查是否存在：
- 编造输入中没有的人物、机构、地点、数据、背景；
- 把不确定信息说成确定事实；
- 把“回应”说成“承认”；
- 把“表态”说成“警告”；
- 把“可能影响”说成“已经导致”；
- 无依据预测；
- 夸大事件影响。

如有关键事实编造，必须 ok=0，rewrite=1。

3. 结构完整

检查是否包含：
- 开头钩子或清晰开场；
- 基本事件交代；
- 至少一个关键事实或画面证据；
- 对事实意义的解释；
- 结尾落点或后续观察点。

如果只是事实堆叠、没有完整结构，应 rewrite=1。
如果结构严重缺失，应 ok=0。

4. 开头吸引力

检查第一句话是否能让观众继续看。

好的开头可以是：
- 悬念；
- 冲突；
- 反差；
- 关键细节；
- 结果前置；
- 核心问题。

避免以下开头：
- “近日……”
- “据了解……”
- “画面中可以看到……”
- “本期视频带你了解……”
- 纯新闻稿式背景介绍。

如果开头平淡但事实正确，可 ok=1, rewrite=1。
如果开头误导或标题党，应 ok=0 或 rewrite=1。

5. 叙事递进

检查文案是否一层一层推进信息。

好的文案应让观众逐步理解：
- 发生了什么；
- 为什么值得关注；
- 关键证据是什么；
- 背后意味着什么；
- 接下来关注什么。

如果文案只是罗列片段，应 rewrite=1。

6. 解说价值

检查文案是否解释了画面和新闻意义。

不合格表现：
- 只说“画面显示”“现场可以看到”；
- 只复述镜头；
- 没有说明为什么重要；
- 没有把画面和新闻主线连接起来。

好的文案应说明：
- 这个画面为什么要看；
- 这句话为什么关键；
- 这个动作或反应说明什么；
- 它和新闻主线有什么关系。

7. 配音自然度

检查文案是否适合 AI TTS。

要求：
- 句子短；
- 节奏清楚；
- 一句话尽量只表达一个意思；
- 避免过长从句；
- 避免复杂书面语；
- 避免难读的连续专有名词堆叠。

建议：
- 单句尽量 8 到 25 个汉字；
- 少数解释句可以稍长，但不宜超过 35 个汉字；
- 每句话适合单独作为字幕一行。

如果长句过多，应 rewrite=1。

8. 字幕友好

检查文案是否适合字幕展示。

要求：
- 断句清楚；
- 不要一整段没有换行；
- 不要一个句子承载多个信息点；
- 不要大量使用复杂标点；
- 不要出现太长字幕行。

如果不适合字幕但可修复，应 rewrite=1。

9. 剪辑匹配

检查 voiceover 是否与输入的 short_video_edit_plan / editing_structure 匹配。

重点检查：
- 是否围绕 core_story_question；
- 是否符合 news_angle；
- 是否覆盖 narrative_arc；
- 是否使用 opening_hook / setup / evidence / ending 等镜头角色；
- 是否讲到了 suggested_voiceover_point；
- 是否存在文案讲了但画面无法支撑的信息；
- 是否有强画面但文案完全没有利用。

如果文案和剪辑规划严重不一致，应 ok=0，rewrite=1。

10. 新闻风格

要求：
- 克制；
- 清楚；
- 专业；
- 有解释；
- 不标题党；
- 不煽动；
- 不口号化；
- 不使用营销号表达。

禁止或强烈避免：
- “震惊”
- “炸裂”
- “惊天”
- “全网沸腾”
- “彻底翻车”
- “全球都没想到”
- “重磅猛料”
- “太可怕了”
- “不得不说”

出现明显营销号风格，应 rewrite=1。
如果伴随事实夸大，应 ok=0。

====================
三、时长检查
====================

请根据中文配音估算时长。

粗略估算：
- 普通中文 AI 配音约每秒 4 到 5 个汉字；
- 也可以按每分钟 240 到 300 个汉字估算。

检查 voiceover 是否和 target_duration_seconds 匹配。

判断：
- 如果估算时长低于目标时长 60%，判 too_short。
- 如果估算时长高于目标时长 140%，判 too_long。
- 其他为 fit。

如果明显 too_short 或 too_long，应 rewrite=1。
如果严重影响成片，应 ok=0。

====================
四、评分规则
====================

请对以下维度打 1-5 分：

- fact_coverage：事实覆盖
- factual_safety：事实安全
- structure：结构完整
- opening_hook：开头吸引力
- narrative_flow：叙事递进
- explanatory_value：解说价值
- voiceover_naturalness：配音自然度
- subtitle_readability：字幕友好
- edit_alignment：剪辑匹配

评分含义：
5 = 很好
4 = 可用
3 = 勉强可用，需要优化
2 = 明显问题
1 = 严重问题

====================
五、通过与重写规则
====================

必须 ok=0, rewrite=1 的情况：
1. 存在关键事实编造；
2. 缺失核心必要事实；
3. 主题和规划明显不一致；
4. 文案结构严重缺失；
5. 文案与镜头规划严重不匹配；
6. 文案明显太短，无法支撑视频；
7. 文案明显太长，无法正常配音；
8. 存在严重夸大、误导或营销号表达。

可以 ok=1, rewrite=1 的情况：
1. 事实正确，但开头不吸引人；
2. 结构基本完整，但叙事较平；
3. 有些句子太长；
4. 有轻微重复；
5. 结尾较弱；
6. 解说价值不足，偏复述画面；
7. 字幕断句不够好。

ok=1, rewrite=0 的情况：
1. 必要事实完整；
2. 没有编造或夸大；
3. 结构完整；
4. 配音自然；
5. 与剪辑规划基本匹配；
6. 时长合理。

====================
六、输出要求
====================

只输出严格 JSON，不要输出解释文字。

输出格式：

{
  "ok": 1,
  "rewrite": 0,
  "severity": "pass",
  "missing": [],
  "scores": {
    "fact_coverage": 5,
    "factual_safety": 5,
    "structure": 4,
    "opening_hook": 4,
    "narrative_flow": 4,
    "explanatory_value": 4,
    "voiceover_naturalness": 5,
    "subtitle_readability": 5,
    "edit_alignment": 4
  },
  "issues": [],
  "rewrite_instructions": [],
  "estimated_voiceover_seconds": 52,
  "duration_fit": "fit"
}

字段说明：

ok:
1 = 可以进入 TTS
0 = 不应进入 TTS

rewrite:
1 = 建议重写或优化
0 = 不需要重写

severity:
只能是 pass / minor / major / critical

missing:
缺失的 required fact 编号数组。
如果没有缺失，返回 []。

issues:
问题列表。每个问题包含：
{
  "type": "fact_coverage/factual_safety/structure/opening_hook/narrative_flow/explanatory_value/voiceover_naturalness/subtitle_readability/edit_alignment/duration/style",
  "severity": "minor/major/critical",
  "description": ""
}

rewrite_instructions:
如果 rewrite=1，给出具体改写方向。
如果 rewrite=0，返回 []。

estimated_voiceover_seconds:
估算配音时长，整数。

duration_fit:
只能是 too_short / fit / too_long。

严格限制：
1. 不要生成新的 voiceover 文案。
2. 不要输出 JSON 以外的文字。
3. 不要因为风格一般就 ok=0，除非影响成片质量。
4. 事实问题优先级高于风格问题。
5. 如果存在关键事实编造，必须 ok=0。
"""
```

# 八、我建议再加一个“自动修复 prompt”

只检查不修复，效率不高。

更合理的流程是：

```text
voiceover_script
→ voiceover_quality_check
→ 如果 rewrite=1
→ voiceover_rewrite
→ 再 quality_check
→ tts
```

这样不需要人工介入。

`voiceover_quality_check` 负责指出问题，`voiceover_rewrite` 负责根据问题重写。

否则你现在即使 `rewrite=1`，后面也不知道怎么处理。

# 九、和 `HIGHLIGHT_REASSEMBLY_TEXT_PROMPT` 的区别

你后面贴的这个：

```python
HIGHLIGHT_REASSEMBLY_TEXT_PROMPT
```

它是原声高光重组，不是 AI 配音。

它的质量标准应该完全不同。

原声高光重组关注的是：

```text
原声是否完整
上下文是否够
转场是否突兀
人物讲话是否被截断
片段是否能独立看懂
是否保留现场情绪
```

而 AI 配音文案检查关注的是：

```text
事实是否准确
解说是否吸引人
叙事是否完整
句子是否适合 TTS
字幕是否好读
文案是否和镜头匹配
```

所以这两个 prompt 不应该混在一起设计。

# 十、最终一句话

`VOICEOVER_QUALITY_CHECK_PROMPT` 不应该只是问：

> 有没有漏事实？有没有编造？

而应该问：

> 这段文案能不能作为一条可发布的 AI 新闻短视频解说，被自然配音、清楚剪辑、准确表达，并且让观众愿意看完？

按照这个标准改，后面的 TTS、字幕、cut_plan、render 才会稳定。
