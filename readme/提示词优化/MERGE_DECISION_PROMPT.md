对，这个问题比 `merge_decision` 当前写法更关键。

现在的 `MERGE_DECISION_PROMPT` 只是在问：

> 多条视频是不是同一事件？是不是同一人物？是不是同一新闻链？

但这还不够。

AI 配音新闻解说真正要判断的是：

> 这些素材碎片放在一起，能不能共同讲清楚一个新闻故事？
> 合并之后，是不是更完整、更有吸引力？
> 还是会变得杂乱、拖沓、角度混乱？

所以 merge 不能只判断“像不像同一新闻”，而应该判断：

> **这些片段是否共同服务于同一个核心问题、同一个新闻角度、同一个叙事弧线。**

# 一、什么素材碎片适合合并成一条新闻解说？

我建议用一句话定义：

> 只要多个片段共同回答同一个新闻问题，并且合并后能形成“背景—现场—关键变化—影响”的完整叙事，就应该合并成一条 AI 配音新闻解说。

比如下面这些情况，应该合并。

---

## 1. 同一事件的不同阶段，应该合并

比如一条新闻里有：

```text
clip_001：事件现场
clip_002：当事人回应
clip_003：官方表态
clip_004：后续影响
```

这不是四条短视频，而是一条完整新闻解说的四个部分。

它们共同服务于一个问题：

> 这件事到底发生了什么？为什么重要？

这种就应该合并。

因为如果拆开，会出现：

* 第一条只有现场，没有解释；
* 第二条只有回应，缺少背景；
* 第三条只有表态，观众不知道前因；
* 第四条只有影响，缺少事实支撑。

这就是“拆碎了新闻链”。

---

## 2. 同一事件的不同证据，应该合并

比如：

```text
clip_001：记者会上一句话
clip_002：现场反应
clip_003：另一个角度的画面
clip_004：后续补充信息
```

这些片段不是不同选题，而是同一判断的证据链。

它们共同证明：

> 这次表态释放了什么信号？

这种也应该合并。

AI 解说可以这样组织：

```text
先抛出核心变化
再放关键发言
然后解释现场反应
最后给出影响判断
```

这比拆成多条更有信息密度。

---

## 3. 同一人物 / 机构围绕同一动作的片段，应该合并

例如：

```text
clip_001：某领导出席活动
clip_002：发表讲话
clip_003：会见相关人士
clip_004：外界反应
```

如果这些片段都围绕同一个动作：

> 这次访问 / 表态 / 会议释放什么信号？

那就应该合并。

但注意，不是只要同一个人物就合并。

关键是：**是否围绕同一个新闻动作**。

---

## 4. 前后片段互相依赖，拆开会缺上下文，应该合并

如果一个片段本身很精彩，但不看前面不知道为什么重要，那它应该和前面的上下文合并。

例如：

```text
clip_001：前面交代冲突背景
clip_002：现场出现关键回应
clip_003：后续双方态度升级
```

`clip_002` 可能最精彩，但单独成片会让观众困惑：

> 他为什么这么说？
> 这句话回应的是谁？
> 这件事为什么重要？

这种就应该合并。

判断标准是：

> 单独看是否能成立？
> 如果不能，就不要拆。

---

## 5. 多个片段共同形成反差 / 转折，应该合并

比如：

```text
clip_001：一开始口径温和
clip_002：后来措辞变强
clip_003：现场气氛变化
clip_004：后续动作升级
```

这些片段合在一起，能讲出一个更吸引人的结构：

```text
表面平静 → 口径变化 → 信号增强 → 后续值得关注
```

这类素材很适合 AI 解说，因为它有“变化”。

新闻解说最吸引人的不是静态事实，而是：

* 态度变化
* 局势变化
* 现场变化
* 措辞变化
* 行动升级
* 前后反差

如果多个片段共同组成这种变化，就应该合并。

---

# 二、哪些素材不应该合并？

不是同一个大主题就一定合并。以下情况不应该合并。

---

## 1. 只是同一个大话题，但不是同一事件，不要合并

比如都属于“中美关系”，但一个是贸易，一个是军事，一个是外交访问。

这不应该合并成一条，除非它们明确构成同一条新闻链。

错误合并：

```text
clip_001：中美贸易谈判
clip_002：南海军事动态
clip_003：外交部例行记者会
```

它们大主题相似，但核心问题不同。

合并后会变成泛泛而谈：

> 最近中美关系有很多变化……

这类视频容易散，不适合短视频。

---

## 2. 只是同一个人物，但动作不同，不要合并

比如：

```text
clip_001：某人物出席经济会议
clip_002：某人物会见外宾
clip_003：某人物参加纪念活动
```

同一个人物，不代表同一条新闻。

除非它们共同回答一个明确问题：

> 这个人物今天一系列动作释放什么政策信号？

否则不要合并。

---

## 3. 角度不同，而且各自能独立成片，不要强行合并

比如同一事件里可能有两个独立角度：

```text
角度A：现场冲突过程
角度B：政策影响分析
```

如果两个角度都足够完整，而且合并会超过 90 秒，或者信息密度太高，就可以分开。

判断标准：

> 合并后是不是更清楚？
> 还是变成两个主题抢注意力？

如果两个主题都很强，反而不要合并。

---

## 4. 画面重复、信息重复，不要因为同一事件就全合并

比如：

```text
clip_001：发言人讲话
clip_002：同一句话另一个机位
clip_003：重复现场画面
clip_004：重复字幕包装
```

这种素材可能同一事件，但不应该全部合并。

合并不是“把所有相关片段都塞进去”，而是挑出最能服务叙事的片段。

重复片段应该只保留：

* 画面更清晰的；
* 信息更完整的；
* 情绪更强的；
* 与解说节点更匹配的。

---

## 5. 合并后叙事链断裂，不要合并

如果合并后变成：

```text
事件A → 突然跳到事件B → 又回到事件A → 再说背景C
```

这种不要合并。

新闻解说需要顺滑的叙事线。

能合并的素材应该可以排成一条自然链路：

```text
原因 → 现场 → 关键变化 → 影响
```

或者：

```text
问题 → 证据 → 解读 → 结论
```

---

# 三、我建议 merge_decision 不再只输出 m 和 groups

你现在的输出：

```json
{
  "m": 1,
  "groups": [["v_001", "v_002"]]
}
```

太简单了。

它只能告诉 pipeline 要不要合并，但不能告诉后续：

* 为什么合并；
* 合并后讲什么核心问题；
* 哪些片段保留；
* 哪些片段只是重复；
* 合并后用什么叙事结构；
* 合并后目标时长怎么控制。

更好的输出应该是：

```json
{
  "m": 1,
  "groups": [
    {
      "group_id": "mg_001",
      "script_ids": ["v_001", "v_002"],
      "merge_reason": "",
      "merged_core_question": "",
      "merged_news_angle": "",
      "merged_story_type": "event_explainer",
      "expected_benefit": "",
      "risk_if_not_merge": "",
      "merge_strategy": "",
      "keep_focus": "",
      "drop_or_compress_points": [],
      "suggested_order": ["v_001", "v_002"]
    }
  ],
  "not_merge_reason": []
}
```

这样 `_merge_short_video_scripts()` 才能真正把多条规划合成一条更好的视频，而不是机械拼接。

# 四、合并判断的核心维度

我建议用 7 个维度判断。

---

## 维度 1：是否同一新闻事件链

判断它们是不是同一个事件的不同阶段。

可以问：

```text
这些片段是否围绕同一件事？
是否有明确的因果、时间、回应、后续关系？
是否属于同一场会议、同一场冲突、同一次访问、同一次发布会？
```

如果是，倾向合并。

---

## 维度 2：是否回答同一个核心问题

这是最重要的。

不是看关键词像不像，而是看它们是否共同回答一个问题。

比如：

```text
这次表态为什么重要？
这场会面释放什么信号？
这起事件为什么引发争议？
这个现场说明局势发生了什么变化？
```

如果多个 script 能合成一个明确问题，就应该合并。

如果每个 script 回答的问题不同，就不要合并。

---

## 维度 3：是否形成完整叙事弧线

适合合并的素材，通常能形成：

```text
背景 → 现场 → 关键细节 → 解读 → 影响
```

或者：

```text
异常点 → 证据 → 变化 → 判断
```

如果两个 script 一个负责背景，一个负责证据，一个负责影响，那就非常适合合并。

如果它们只是并列信息，没有递进关系，就不一定合并。

---

## 维度 4：拆开后是否缺上下文

这是 merge 的强触发条件。

如果拆开后某条会变成：

```text
只有一句话，没有前因
只有现场，没有解释
只有反应，没有事件
只有结果，没有过程
```

那就应该合并。

---

## 维度 5：合并后是否更吸引人

不是所有合并都好。

要判断合并后是否增强：

* 悬念；
* 反差；
* 冲突；
* 信息递进；
* 事实完整度；
* 结尾落点。

如果合并后只是变长，但没有更好看，不合并。

---

## 维度 6：是否存在信息重复

如果两条 script 其实讲的是同一个点，只是用了不同片段，那不要输出两条，也不要简单合并成长视频。

应该合并，但压缩重复信息。

例如：

```json
"merge_strategy": "merge_and_deduplicate"
```

意思是：

> 合并为一条，但只保留信息最强的镜头，重复事实不重复讲。

---

## 维度 7：合并后时长是否合理

AI 配音新闻短视频不是越完整越好。

建议规则：

```text
30-45 秒：单点解释
45-60 秒：普通事件解说
60-90 秒：复杂事件或多阶段新闻
超过 90 秒：除非信息非常强，否则不建议合并
```

如果合并后预计超过 90 秒，就要考虑：

* 是否压缩重复片段；
* 是否只保留主线；
* 是否拆成两条角度明确的视频。

---

# 五、可落地的合并决策规则

我建议设计一个评分逻辑，让模型更稳定。

每一对或每一组 scripts 评估 6 项，每项 0-2 分：

| 维度      | 0 分  | 1 分     | 2 分         |
| ------- | ---- | ------- | ----------- |
| 事件一致性   | 不同事件 | 同主题但弱关联 | 同一事件链       |
| 核心问题一致性 | 问题不同 | 部分重叠    | 回答同一问题      |
| 叙事互补性   | 没有互补 | 有一些补充   | 明显形成完整叙事    |
| 上下文依赖   | 可独立  | 部分依赖    | 拆开明显缺上下文    |
| 合并吸引力   | 变散   | 一般      | 更有悬念/递进/完整性 |
| 重复风险    | 重复严重 | 有重复可压缩  | 互补为主        |

建议判断：

```text
总分 >= 8：建议合并
总分 5-7：谨慎合并，只有在拆开明显太碎时合并
总分 <= 4：不合并
```

但要加两个强规则：

```text
如果是明显不同事件，即使总分高，也不合并。
如果拆开后明显缺上下文，即使总分一般，也倾向合并。
```

# 六、哪些素材碎片适合进入同一条新闻解说稿？

这可以作为 `merge_decision` 的核心原则。

一条 AI 新闻解说稿的素材最好包含以下几类中的 3 类以上：

```text
1. 事件触发点：发生了什么
2. 现场关键画面：观众能看到什么
3. 核心发言/动作：新闻事实的关键证据
4. 背景上下文：为什么这件事重要
5. 变化/冲突/反差：这条新闻为什么值得讲
6. 后续影响/观察点：结尾落在哪里
```

如果多个碎片分别对应这些位置，它们就非常适合合并。

比如：

```text
v_001：现场发生什么
v_002：关键人物回应
v_003：外界反应
```

这就是完整结构。

但如果是：

```text
v_001：新闻A现场
v_002：新闻B背景
v_003：新闻C评论
```

就不适合合并。

# 七、合并后应该怎么组织素材？

合并不是按原视频顺序简单拼接。

AI 配音模式下，应该按“叙事功能”重排。

推荐顺序：

```text
1. 最能抓人的画面 / 事实
2. 必要背景
3. 关键证据
4. 冲突或变化
5. 影响或结尾判断
```

也就是：

```text
hook → setup → evidence → development → ending
```

有时候，最精彩的片段不在原视频开头，也应该提前用作开头。

例如：

```text
原始顺序：
背景介绍 → 会场画面 → 关键发言 → 外界反应

短视频顺序：
关键发言 → 背景介绍 → 会场画面 → 外界反应
```

因为短视频要先抓住观众。

# 八、推荐新版 MERGE_DECISION_PROMPT

下面这个版本更适合你的 AI 配音新闻解说系统。

```python
MERGE_DECISION_PROMPT = r"""

你的任务不是简单判断它们是否有相同人物、相同地点或相同话题，而是判断：

这些短视频规划是否共同服务于同一个新闻故事？
它们是否应该合并成一条更完整、更清楚、更吸引人的 AI 配音新闻解说？

====================

AI 配音新闻短视频不是新闻稿朗读，也不是片段堆叠。

一条好的新闻解说应该围绕一个核心问题展开，并形成清楚的叙事链：

钩子 → 发生了什么 → 为什么重要 → 关键证据/细节 → 影响或结尾落点

因此，只有当多个 scripts 可以共同回答同一个核心问题，并且合并后能形成更完整的叙事时，才建议合并。

默认不要生成很多碎视频。
如果多个 scripts 属于同一新闻链，拆开后会缺少上下文，应建议合并。

但也不要把只是同一大话题、同一人物、同一地区的不同事件强行合并。

====================
二、应该合并的情况
====================

以下情况应强烈建议合并：

1. 同一事件链的不同阶段
   例如：事件现场、当事人回应、官方表态、后续影响。

2. 同一核心问题的不同证据
   例如：一个片段提供关键发言，另一个片段提供现场反应，第三个片段提供背景信息。

3. 前后片段互相依赖
   如果拆开后其中一条视频会缺少前因、背景、事实支撑或结尾落点，应合并。

   - 背景 → 现场 → 关键变化 → 影响

5. 多条规划其实只是同一新闻的不同角度
   如果这些角度可以自然合成一条完整解说，而不会造成混乱，应合并。

   如果单条视频缺少独立成立的新闻价值，应合并。

以下情况不要合并：

1. 明显不同新闻事件
   即使属于同一大话题，也不要强行合并。

2. 只是同一个人物，但新闻动作不同
   同一个人出现在多个事件中，不代表应该合并。

3. 只是同一地区、同一机构、同一议题
   如果没有明确因果、回应、时间推进或事实链关系，不要合并。

4. 合并后核心问题变得模糊
   如果无法用一句话说明合并后视频主要回答什么问题，不要合并。

5. 合并后叙事变散
   如果合并会导致多个主题抢注意力，不要合并。

6. 两条视频各自已经完整且角度不同
   如果每条都能独立成立，而且合并会拖长或削弱重点，不要合并。

7. 合并后预计超过 90 秒且无法压缩
   除非信息密度很高，否则不建议合并成长视频。

====================
四、判断维度

请从以下维度判断每组 scripts 是否应该合并：

1. 事件一致性
   它们是否属于同一新闻事件链？

2. 核心问题一致性
   它们是否共同回答同一个核心问题？

3. 叙事互补性
   它们是否分别承担背景、现场、证据、变化、影响等不同叙事功能？

4. 上下文依赖
   拆开后是否会导致某条视频缺少必要上下文？

5. 合并后的吸引力

- 核心问题一致性：0-2

如果建议合并，请不要只按原顺序拼接。

1. 合并后的核心问题是什么？
2. 合并后的新闻角度是什么？
3. 哪些内容保留为主线？
4. 哪些内容应该压缩或去重？
5. 合并后建议采用什么叙事类型？
6. 合并后片段顺序应该如何组织？

推荐叙事顺序：

opening_hook → setup → evidence → development/climax → ending

也可以根据素材选择：
- event_explainer
- detail_focus
- conflict_escalation
- contrast_reveal

====================
七、输出格式
====================

只输出 JSON，不要输出解释文字。

输出格式如下：

{
  "m": 1,
  "groups": [
    {
      "group_id": "mg_001",
      "script_ids": ["v_001", "v_002"],
      "merge_decision": 1,
      "score": {
        "event_consistency": 2,
        "core_question_consistency": 2,
        "narrative_complementarity": 2,
        "context_dependency": 1,
        "merge_attractiveness": 2,
        "dedup_feasibility": 1,
        "total": 10
      },
      "merge_reason": "",
      "merged_core_question": "",
      "merged_news_angle": "",
      "merged_story_type": "event_explainer",
      "expected_benefit": "",
      "risk_if_not_merge": "",
      "merge_strategy": "merge_and_reorder",
      "keep_focus": "",
      "drop_or_compress_points": [],
      "suggested_order": ["v_001", "v_002"]
    }
  ],
  "not_merge": [
    {
      "script_ids": ["v_003", "v_004"],
      "reason": "",
      "core_difference": ""
    }
  ]
}

字段说明：

- m:
  只要存在任意建议合并的 group，则为 1。
  如果没有任何建议合并的 group，则为 0。

- groups:
  所有建议合并的视频组。

- merge_decision:
  当前 group 是否建议合并，1 表示合并。

- merge_reason:
  为什么这些 scripts 应该合并。

- merged_core_question:
  合并后这条视频主要回答什么问题。

- merged_news_angle:
  合并后的新闻角度。

- merged_story_type:
  合并后建议采用的叙事类型，只能是：
  event_explainer / detail_focus / conflict_escalation / contrast_reveal

- expected_benefit:
  合并后比拆开更好的地方。

- risk_if_not_merge:
  如果不合并，会出现什么问题，例如太碎、缺上下文、重复、主线不完整。

- merge_strategy:
  合并策略，只能使用：
  merge_and_reorder：合并并按叙事重排
  merge_and_deduplicate：合并并去重
  merge_as_context_plus_evidence：一个作为背景，一个作为证据
  merge_as_setup_and_payoff：一个铺垫，一个收束
  merge_as_conflict_chain：合并成冲突升级链

- keep_focus:
  合并后必须聚焦的主线。

- drop_or_compress_points:
  合并时应该删掉或压缩的重复点、弱信息点。

- suggested_order:
  合并后建议的 script 顺序，不一定等于输入顺序。

- not_merge:
  不建议合并的组合及原因。

====================
八、严格限制
====================

1. 不得因为同一人物就强行合并。
2. 不得因为同一地区就强行合并。
3. 不得因为同一大话题就强行合并。
4. 不得合并明显不同事件。
5. 不得让合并后视频失去清晰核心问题。
6. 不得输出 JSON 以外的文字。
"""
```

```json
{

  "groups": [["v_001", "v_002"]]
```

那 prompt 可以先优化判断逻辑，输出仍保持旧结构。

兼容版如下：

```python
MERGE_DECISION_PROMPT = r"""
你是一个资深新闻短视频总编，负责判断多条 AI 配音短视频规划是否应该合并。

你的核心任务是判断：
这些 scripts 是否共同服务于同一个新闻故事？
它们是否应该合并成一条更完整、更清楚、更吸引人的 AI 配音新闻解说？

不要只根据人物、地点、机构、话题相同就合并。
只有当多个 scripts 能共同回答同一个核心问题，并且合并后形成更完整叙事时，才建议合并。

====================
应该合并的情况
====================

1. 多条 scripts 属于同一新闻事件链的不同阶段：
   例如现场、回应、表态、后续影响。

2. 多条 scripts 共同回答同一个核心问题：
   例如“这次表态为什么引发关注？”、“这场会面释放什么信号？”

3. 多条 scripts 之间存在明显上下文依赖：
   如果拆开后某条视频会缺少背景、前因、事实支撑或结尾落点，应合并。

4. 多条 scripts 可以形成完整叙事：
   例如：
   - 背景 → 现场 → 关键变化 → 影响
   - 异常点 → 证据 → 解读 → 结论
   - 冲突焦点 → 双方回应 → 升级节点 → 后续观察

5. 多条 scripts 单独看太短、太碎、信息不完整：
   如果合并后更清楚、更有吸引力，应合并。

6. 多条 scripts 信息重复：
   如果它们实际讲的是同一个点，应合并为一条，后续去重压缩，而不是输出多条重复视频。

====================
不应该合并的情况
====================

1. 明显不同新闻事件，不合并。
2. 只是同一人物，但新闻动作不同，不合并。
3. 只是同一地区、机构或大话题，但没有明确新闻链关系，不合并。
4. 合并后无法用一句话说明核心问题，不合并。
5. 合并后叙事变散、多个主题抢重点，不合并。
6. 两条视频各自完整且角度不同，合并会拖长或削弱重点，不合并。
7. 合并后预计超过 90 秒且无法压缩，不建议合并。

====================
判断方法
====================

请从以下维度内部判断：

1. 是否同一事件链。
2. 是否回答同一个核心问题。
3. 是否形成叙事互补。
4. 拆开后是否缺上下文。
5. 合并后是否更吸引人。
6. 是否有重复但可压缩。
7. 合并后时长是否合理。

强规则：
- 明显不同事件：不合并。
- 拆开明显缺上下文：优先合并。
- 无法形成清晰核心问题：不合并。
- 只是同人物、同地区、同大话题：不合并。

====================
输出要求
====================

只输出 JSON，不要输出解释文字。

格式如下：

{
  "m": 1,
  "groups": [["v_001", "v_002"]]
}

如果没有任何需要合并的组：

{
  "m": 0,
  "groups": []
}

groups 中只放确实应该合并的 short_video_id 分组。
不要输出不确定的组合。
不要输出 JSON 以外的任何文字。
"""
```

# 十、我的建议：merge_decision 最好不要放在 short_video_edit_plan 后面

从架构上讲，你现在是：

```text
candidate_refine
→ short_video_edit_plan
→ merge_decision
→ voiceover_script
→ cut_plan
```

这个顺序可以跑，但逻辑上有点绕。

因为 `short_video_edit_plan` 已经决定生成几条视频了，后面又用 `merge_decision` 判断要不要合并，说明前一步本身不够稳定。

更理想的方式是：

```text
candidate_refine
→ story_grouping
→ short_video_edit_plan
→ voiceover_script
→ cut_plan
```

也就是先做“新闻故事分组”，再做短视频规划。

`story_grouping` 判断：

```text
哪些候选片段属于同一条新闻故事？
每个故事回答什么核心问题？
每个故事能不能独立成片？
每个故事适合 AI 配音还是原声重组？
```

然后 `short_video_edit_plan` 只在每个故事组内规划视频。

这样比“先拆再合”更自然。

不过如果你现在不想大改 pipeline，保留 `merge_decision` 也可以。那它就必须从“同事件判断”升级为：

> **新闻故事完整性判断。**

# 十一、最终判断标准可以浓缩成这 5 句话

你可以直接写进文档：

```text
1. 能共同回答同一个新闻问题的素材，应该合并。
2. 属于同一事件链不同阶段的素材，应该合并。
3. 拆开后缺上下文、缺证据、缺结尾的素材，应该合并。
4. 只是同人物、同地区、同大话题，但没有明确新闻链关系的素材，不应合并。
5. 合并后如果不能形成一个清晰、有递进、有落点的新闻故事，就不应合并。
```

这个标准比“同事件就合并，不同事件就不合并”更适合 AI 新闻解说。
