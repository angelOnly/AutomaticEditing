可以。`candidate_refine` 这一步本质上不是重新“发现高光”，而是对已经找到的候选片段做一次**质量闸门 + 用途分流 + 叙事归类 + 排序**。

也就是说，它要回答：

> 这个片段是不是值得继续留在系统里？
> 留下来以后，它更适合 AI 配音剪辑，还是原声新闻重组？
> 它能不能单独被理解？
> 它需要和哪些片段放在一起？
> 它在同一新闻故事里优先级高不高？

---

# 一、candidate_refine 的核心判断目标

前面的 `highlight_detection` 或 `content_analysis` 可能会把很多“看起来像高光”的片段都抓出来，但这些片段里面会混着几类问题：

有的是真高光；
有的是重复信息；
有的是只有画面但没事实；
有的是只有一句话，需要上下文才懂；
有的是适合 AI 配音，但不适合原声重组；
有的是原声很有价值，但画面一般；
有的是可以作为主片段，有的只能作为补充片段。

所以 `candidate_refine` 不应该只判断“精彩不精彩”，而应该判断：

**这个片段在后续成片里有没有实际使用价值。**

---

# 二、字段设计应该怎么理解

你现在的字段是：

```json
{
  "k": 1,
  "u": "both",
  "i": 1,
  "c": 0,
  "g": "g1",
  "r": 1
}
```

建议定义成这样：

| 字段  | 含义      | 判断重点                   |
| --- | ------- | ---------------------- |
| `k` | 是否保留    | 片段有没有继续使用价值            |
| `u` | 使用方向    | 适合 AI 配音、原声重组、都适合，还是丢弃 |
| `i` | 是否可独立理解 | 单独看是否知道发生了什么           |
| `c` | 是否需要上下文 | 是否必须依赖前后片段解释           |
| `g` | 故事组     | 属于同一新闻事件/同一叙事线         |
| `r` | 组内优先级   | 同组片段谁更关键               |

---

# 三、第一层：是否保留 `k`

## 1. `k=1`：应该保留的片段

保留的核心标准是：

> 这个片段至少能承担一个明确的新闻功能。

新闻功能包括：

事件事实；
现场证明；
关键人物表态；
民众影响；
数据结果；
冲突转折；
专家解释；
后续安排。

也就是说，一个片段不一定要“很震撼”，只要它对新闻叙事有用，就应该保留。

---

## 2. 建议保留的片段类型

### A. 核心事实片段

能说明新闻最基本事实：

发生了什么；
谁参与；
在哪里；
造成什么结果；
目前进展如何。

比如：

“当地时间周二，某地发生爆炸。”
“警方称已有多人受伤。”
“政府宣布进入紧急状态。”

这种片段必须保留，因为它是新闻骨架。

---

### B. 现场证明片段

有现场画面、现场声音、记者连线、一线采访。

它的价值是：

**证明这不是抽象信息，而是真实发生的事件。**

比如：

救援现场；
冲突现场；
灾害画面；
群众撤离；
发布会现场；
记者在现场报道。

这类片段对原声重组尤其重要。

---

### C. 关键人物讲话片段

但不是所有讲话都保留。

应该保留的是：

首次回应；
明确表态；
宣布措施；
承认/否认；
警告；
道歉；
说明责任；
透露后续安排。

不应该保留的是：

寒暄；
套话；
重复立场；
没有新信息的外交辞令；
纯总结但没有事实增量。

---

### D. 民众影响片段

新闻里非常重要。

只要片段讲清楚“影响谁、怎么影响”，就值得保留。

比如：

居民生活受影响；
交通中断；
学校停课；
物价上涨；
医院压力；
企业成本变化；
就业受影响；
消费者权益变化。

这类片段能把新闻从“事件”变成“和观众有关”。

---

### E. 数据和结果片段

有明确数字、规模、结果、变化趋势。

比如：

伤亡人数；
经济损失；
投票结果；
政策覆盖人数；
市场涨跌幅；
救援人数；
撤离人数；
时间节点。

这类片段通常应该保留，因为它能量化事件严重程度。

---

### F. 转折和升级片段

这类是强高光。

比如：

局势升级；
官方说法变化；
当事方反驳；
谈判破裂；
判决结果；
新证据出现；
市场突然波动；
民众反应扩大。

这类片段往往适合排在视频中段，制造新闻推进感。

---

### G. 专家解读片段

专家解读只有在“有明确结论”时才保留。

应该保留：

解释原因；
判断趋势；
说明影响；
澄清误解；
补充背景。

应该丢弃：

泛泛而谈；
术语堆砌；
没有结论；
重复主持人口播；
时间太长但信息很少。

---

## 3. `k=0`：应该丢弃的片段

建议明确写进 prompt：

以下片段即使被前一步选为候选，也应该丢弃：

无信息空镜；
重复背景；
片头片尾；
节目包装；
广告；
无关转场；
主持人泛泛引入；
没有事实增量的口播；
套话讲话；
信息被其他片段更好覆盖；
音频不可用；
画面严重模糊；
必须依赖大量前文才能理解且没有补充价值。

---

# 四、第二层：用途判断 `u`

`u` 是这个步骤最关键的字段之一。因为 AI 配音模式和原声重组模式需要的片段不是完全一样的。

建议四种取值：

```json
"u": "av"     // AI voiceover
"u": "re"     // reassembly
"u": "both"
"u": "drop"
```

---

## 1. `u = "av"`：适合 AI 配音模式

AI 配音模式的核心是：

> 画面有价值，信息可以由 AI 解说补足。

所以它不一定要求原声完整、讲话精彩、上下文自洽。

适合 AI 配音的片段包括：

现场画面强，但原声杂乱；
画面能表现事件，但缺少清晰同期声；
信息点分散，可以通过 AI 解说整合；
画面具有视觉代表性；
多个素材需要跨源整合；
现场同期声价值不高，但画面价值高。

比如：

灾害现场的航拍；
群众排队画面；
救援队行动；
市场、街道、医院、学校画面；
会议现场但讲话内容不关键；
冲突现场但声音嘈杂。

这些片段适合交给 AI 配音重新解释。

### 为什么这样判断？

因为 AI 配音模式不依赖原声叙事，它依赖的是：

**画面可用性 + 新闻事实可解释性。**

只要画面能支持 AI 文案，这个片段就有价值。

---

## 2. `u = "re"`：适合原声重组模式

原声重组模式的核心是：

> 片段的原声本身有新闻价值，且可以直接拼接成新闻视频。

所以它对音频、话语完整度、原声信息密度要求更高。

适合原声重组的片段包括：

记者现场报道完整；
重要人物讲话完整；
发布会回答关键问题；
专家一句话判断明确；
当事人/民众采访有代表性；
现场同期声有强新闻冲击；
片段开头和结尾比较自然，方便剪辑。

比如：

“总统表示将采取进一步措施。”
“当地居民说已经停水两天。”
“专家判断这会影响未来三个月供应链。”
“记者现场说明目前救援已经进入第二阶段。”

### 为什么这样判断？

因为原声重组不能靠 AI 旁白补洞。

片段本身必须具备：

原声清晰；
语义完整；
信息密度高；
前后衔接自然；
不严重依赖原视频上下文。

---

## 3. `u = "both"`：两种模式都适合

这是最高价值片段。

它通常同时具备：

画面有现场感；
原声有清晰信息；
能独立表达事实；
新闻价值高；
可以作为主干片段。

比如：

记者在事故现场连线，画面是救援现场，口播说明伤亡和救援进展；
重要人物在发布会上宣布政策，画面和声音都清楚；
居民采访说出具体影响，同时画面能看到受影响场景；
专家短句判断明确，且配有事件相关画面。

### 为什么这样判断？

因为这种片段无论走 AI 配音还是原声重组，都有用。

在后续流程里应该优先使用。

---

## 4. `u = "drop"`：不适合任何模式

即使 `k` 理论上也可以是 0，但建议 `u=drop` 作为冗余保护。

适合标 drop 的情况：

信息重复；
无新闻价值；
画面和声音都不可用；
上下文缺失严重；
内容偏离主题；
只有转场或空镜；
质量过差。

---

# 五、第三层：独立性判断 `i`

`i` 表示：

> 这个片段单独拿出来，观众能不能大致理解它在说什么。

建议：

```json
"i": 1   // 可以独立理解
"i": 0   // 不能独立理解
```

---

## 1. `i=1` 的判断标准

片段里至少包含以下信息中的两类：

事件主体；
发生动作；
地点或背景；
结果或影响；
人物身份；
明确时间或阶段；
画面能辅助理解。

比如：

“当地时间周二，某市发生严重洪灾，目前已有上万人撤离。”
“警方表示，嫌疑人已被控制。”
“专家认为，这将推高未来数周油价。”

这些都可以独立理解。

---

## 2. `i=0` 的判断标准

片段本身说不清楚它在讲什么。

比如：

“这也是为什么他们今天做出这个决定。”
“问题的关键就在这里。”
“他刚才的说法引发外界关注。”
“我们接着来看下一段画面。”

这些句子没有上下文就无法理解。

还有一种情况：

画面有冲击力，但没有说明发生了什么。

比如只有爆炸画面、群众奔跑、警车经过，但没有任何解释。这种画面可以适合 AI 配音，但不算独立。

---

## 3. 为什么要判断独立性？

因为后面两个流程需求不同：

AI 配音模式可以使用 `i=0` 的画面片段，因为 AI 解说能补上下文。
原声重组模式更适合使用 `i=1` 的片段，因为它不能依赖额外解释。

所以：

`i=1` 的片段可以作为主片段；
`i=0` 的片段更适合作为补充画面、B-roll、情绪/现场辅助片段。

---

# 六、第四层：上下文需求 `c`

`c` 表示：

> 这个片段是否需要其他片段配合，才能被正确理解。

建议：

```json
"c": 0   // 不需要上下文
"c": 1   // 需要上下文
```

注意：`i` 和 `c` 不是完全重复。

---

## 1. `i` 和 `c` 的区别

`i` 是单独能不能看懂。
`c` 是为了准确理解，需不需要搭配其他片段。

举例：

### 情况 A：`i=1, c=0`

片段完全自洽。

比如：

“当地发生地震，目前已造成至少20人受伤，救援仍在进行。”

这是最好的主干片段。

---

### 情况 B：`i=1, c=1`

片段能看懂，但最好加上下文。

比如：

“这一决定将影响数百万家庭。”

这句话能理解，但观众需要知道“哪项决定”。

所以它可以独立表达影响，但需要前面有政策片段。

---

### 情况 C：`i=0, c=1`

片段单独看不懂，必须依赖上下文。

比如：

“这正是争议的核心。”

这种一般不适合原声重组，除非前后片段一起保留。

---

### 情况 D：`i=0, c=0`

理论上很少见。
如果单独看不懂，一般就需要上下文。除非它只是纯视觉素材，用于 AI 配音 B-roll。

比如：

只有灾区航拍，没有口播。
画面本身不解释具体事件，但可以作为视觉素材。

这种可以是：

```json
{
  "k": 1,
  "u": "av",
  "i": 0,
  "c": 0
}
```

意思是：不靠它讲事实，只把它当画面素材。

---

## 2. 为什么要有 `c`？

因为原声重组最怕出现“断句式拼接”。

比如模型选了一个片段：

“他表示，这一结果令人遗憾。”

如果没有前文，观众不知道：

他是谁；
什么结果；
为什么遗憾。

所以 `c=1` 可以提醒后续 `highlight_reassembly_plan`：

这个片段不能单独使用；
如果使用，必须和同组内前置解释片段组合；
否则应该降低优先级。

---

# 七、第五层：故事组 `g`

`g` 的作用是把候选片段按新闻故事归类。

这个非常重要，尤其你说的是“多个新闻碎片选取高光片段重新组合”。

多个视频源里可能有：

同一事件的不同角度；
不同新闻事件；
同一主题下的多个子事件；
同一个事件的背景、现场、影响、回应、专家解读。

如果不分组，后面的重组就容易乱拼。

---

## 1. `g` 应该按什么分？

建议按“同一新闻事件 / 同一叙事主线”分组，而不是按视频来源分组。

不要这样分：

source_1 一组；
source_2 一组；
source_3 一组。

应该这样分：

g1：某国选举结果及影响；
g2：某地洪灾救援；
g3：某企业财报与市场反应；
g4：某政策发布与民生影响。

---

## 2. 同一故事组的判断标准

满足以下任意几个，就应该归为同一组：

同一事件；
同一地点；
同一人物；
同一政策；
同一事故；
同一冲突；
同一时间线；
同一影响对象；
同一后续进展。

比如：

片段 A：事故现场；
片段 B：警方发布会；
片段 C：居民采访；
片段 D：专家分析事故原因。

这四个都应该是同一个 `g`。

---

## 3. 不应该混为一组的情况

同一新闻节目里相邻出现，但事件无关；
都是国际新闻，但不是同一事件；
都是经济新闻，但一个讲股市，一个讲就业；
都是某国相关，但一个讲选举，一个讲灾害；
同一人物出现，但参与的是不同事件。

---

## 4. 为什么要分故事组？

因为后续有两个用途：

### 对 AI 配音模式

同组片段可以被综合成一个 AI 解说短视频。
不同组片段不要混在一个视频里，除非产品明确要做“新闻合集”。

### 对原声重组模式

同组片段可以按新闻逻辑排序：

事实导入 → 现场 → 表态 → 影响 → 解读 → 后续。

如果不分组，原声重组会出现不同新闻事件乱拼的问题。

---

# 八、第六层：组内优先级 `r`

`r` 是组内排序，不是全局排序。

建议定义：

```json
"r": 1   // 最高优先级
"r": 2
"r": 3
...
```

数字越小，优先级越高。

---

## 1. 排序原则

同一个故事组里，优先级应该按“新闻主干价值”排，而不是按画面刺激程度排。

推荐优先级：

### r=1：主干核心片段

满足以下条件之一：

直接说明事件核心事实；
最完整的现场报道；
最关键人物表态；
最重要结果或转折；
最能代表整条新闻。

它通常可以作为视频开头或主干。

---

### r=2：强补充片段

包括：

现场补充；
民众影响；
关键数据；
当事方回应；
专家明确判断。

它们不是唯一主干，但能增强新闻完整性。

---

### r=3：辅助片段

包括：

环境画面；
一般背景；
较弱采访；
重复但角度略不同的信息；
B-roll 画面。

适合在时长允许时使用。

---

### r=4 或更低：低优先级保留片段

这些片段有一定价值，但不应该优先使用：

信息重复；
需要上下文；
表达不够完整；
画面可用但新闻信息较弱；
只适合补画面。

---

## 2. 为什么 `r` 要按组内排？

因为不同故事之间很难直接比较。

一个小新闻的核心事实片段，可能比一个大新闻的辅助画面更重要。
如果全局排序，模型可能会把不同故事混在一起，影响重组质量。

所以更合理的是：

先用 `g` 确定故事；
再用 `r` 选同一故事里的主干片段；
后续再由 `highlight_reassembly_plan` 决定做几个视频、每个视频用哪个故事组。

---

# 九、可以设计一套评分模型

为了让 prompt 判断更稳定，可以先让模型隐式按这几个维度打分，但输出仍保持极简 JSON。

不要一定让它输出分数，否则 JSON 会变大。
但 prompt 里可以告诉它按这些标准判断。

---

## 1. 新闻事实价值

判断：

是否包含核心事实？
是否说明发生了什么？
是否有明确人物、地点、结果？

高：核心事实明确。
中：有部分事实。
低：只有背景或空泛描述。

---

## 2. 公共影响价值

判断：

是否影响民众？
是否涉及安全、民生、经济、政策、社会秩序？
是否说明影响范围？

高：直接说明影响谁、影响多大。
中：隐含影响。
低：与公众关系弱。

---

## 3. 原声价值

判断：

原声是否清楚？
讲话是否完整？
有没有关键信息？
是否适合直接拼入原声视频？

高：原声完整、清晰、有新闻价值。
中：部分可用。
低：嘈杂、碎片化、无有效信息。

---

## 4. 画面价值

判断：

画面是否能证明新闻事实？
是否有现场感？
是否能支撑 AI 配音？
是否比普通空镜更有信息量？

高：强现场、强证明。
中：有相关画面。
低：普通空镜或重复画面。

---

## 5. 叙事功能

判断：

这个片段在一条新闻里承担什么角色？

导入；
现场；
表态；
影响；
解读；
转折；
后续。

高：角色明确且不可替代。
中：有辅助作用。
低：没有明确作用。

---

## 6. 去重价值

判断：

这个片段的信息是否已被其他片段更好表达？

如果有一个更清晰、更完整、更权威的片段表达了同样信息，那么当前片段应降低优先级，甚至 `k=0`。

# 十、具体决策规则

可以这样写成规则。

---

## 规则 1：没有新闻功能，直接丢弃

如果片段不能承担以下任一功能：

事实、现场、表态、影响、数据、转折、解读、后续。

则：

```json
{
  "k": 0,
  "u": "drop"
}
```

原因：

新闻高光不是素材堆砌，必须服务叙事。

---

## 规则 2：画面强但原声弱，保留给 AI 配音

如果片段：

画面有现场感；
但原声嘈杂、断裂、无关或信息不足；
需要 AI 解说补充事实。

则：

```json
{
  "k": 1,
  "u": "av",
  "i": 0,
  "c": 0
}
```

原因：

AI 配音模式可以用画面做视觉证据，由文案补充逻辑。

---

## 规则 3：原声强但画面一般，保留给原声重组

如果片段：

讲话或记者口播有明确新闻信息；
原声清晰；
语义完整；
即使画面一般也能传递关键事实。

则：

```json
{
  "k": 1,
  "u": "re"
}
```

原因：

原声重组靠的是同期声价值，不一定要求画面非常刺激。

---

## 规则 4：音画都强，标为 both

如果片段：

画面有现场感；
原声有清晰事实；
能独立理解；
新闻价值强。

则：

```json
{
  "k": 1,
  "u": "both",
  "i": 1,
  "c": 0,
  "r": 1
}
```

原因：

这是最高价值片段，后续两个模式都应该优先考虑。

---

## 规则 5：需要上下文但有价值，可以保留但降级

如果片段本身有价值，但必须依赖前后文：

```json
{
  "k": 1,
  "c": 1,
  "i": 0
}
```

并且 `r` 不应太高，除非它是关键转折片段。

原因：

这类片段不能随便单独拼接，否则观众会看不懂。

---

## 规则 6：重复信息只保留最优表达

如果多个片段说同一件事，优先保留：

信息更完整的；
来源更权威的；
原声更清楚的；
画面更贴近现场的；
更短更密集的；
更适合作为主干的。

其他重复片段可以：

`k=0`，或者 `k=1` 但 `r` 降低。

原因：

重组视频时间有限，重复会拖慢节奏。

---

## 规则 7：同组片段要有角色互补

一个故事组里最好保留不同功能的片段，而不是全是同一种。

理想结构是：

核心事实片段；
现场片段；
人物表态；
民众影响；
专家解读；
后续安排。

如果同组里有 10 个候选片段，应该优先保留能组成完整新闻链条的片段，而不是只保留最刺激的几个画面。

原因：

新闻重组要像一条完整新闻，不是热点画面合集。

---

# 十一、建议的判断流程

可以让模型按这个流程判断每个候选片段：

---

## Step 1：先判断是否有新闻功能

问：

这个片段有没有新增事实、现场证明、表态、影响、数据、转折、解读或后续？

没有：`k=0, u=drop`
有：进入下一步。

---

## Step 2：判断音频和画面价值

问：

原声是否有独立新闻价值？
画面是否有现场证明价值？

结果：

原声强、画面强：`u=both`
原声强、画面弱：`u=re`
原声弱、画面强：`u=av`
两者都弱：`u=drop`

---

## Step 3：判断独立性

问：

观众单独看这个片段，是否知道大概发生了什么？

能：`i=1`
不能：`i=0`

---

## Step 4：判断上下文需求

问：

这个片段如果被使用，是否必须搭配前后片段才能正确理解？

需要：`c=1`
不需要：`c=0`

---

## Step 5：分配故事组

问：

它属于哪个新闻事件/叙事线？

同一事件、同一政策、同一冲突、同一地点、同一人物主线，归为同一 `g`。

---

## Step 6：组内排序

问：

在这个故事组里，它是主干、强补充、辅助，还是低优先级？

主干：`r=1`
强补充：`r=2`
辅助：`r=3`
低优先级：`r=4+`

---

# 十三、我建议你把 `candidate_refine` 的定位改清楚

现在这个 prompt 最容易出问题的地方是：

模型会把 `keep` 理解成“是不是精彩”，而不是“后续成片有没有使用价值”。

建议你在提示词里明确：

> Do not keep a clip only because it looks visually dramatic. Keep it only if it provides factual value, public impact, authoritative statement, useful scene evidence, expert interpretation, or narrative function for a news video.

中文意思就是：

**不要因为画面刺激就保留。只有当它对新闻事实、公共影响、权威表态、现场证明、专家解释或叙事结构有价值时，才保留。**

---

# 十四、推荐的最终判断标准

可以压缩成一句核心规则：

> 保留一个新闻候选片段，必须因为它能帮助观众理解“发生了什么、为什么重要、影响谁、谁在回应、接下来怎样”中的至少一个问题。

进一步：

如果它回答的是核心事实，优先级最高。
如果它证明现场，适合保留。
如果它表达权威立场，适合原声重组。
如果它展示民众影响，适合增强共情和公共价值。
如果它解释原因趋势，适合作为补充。
如果它只是重复、空镜、套话、转场，就丢弃。

# 十五、可以直接写进 prompt 的版本

下面这段可以作为 `CANDIDATE_REFINE_PROMPT` 的核心判断规则：

```text
You are refining candidate clips for a news video system.

For each candidate clip, decide whether it should be kept, how it should be used, whether it can stand alone, whether it needs context, which story group it belongs to, and its rank within that group.

A clip should be kept only if it provides at least one clear news function:
- core fact: what happened, who is involved, where, when, result
- scene evidence: on-site footage, reporter standup, rescue, conflict, meeting, press conference, public reaction
- authoritative statement: official response, key person speech, announcement, denial, warning, apology, measure
- public impact: casualties, livelihood, traffic, economy, policy, safety, education, health, ordinary people affected
- key data: numbers, scale, timeline, loss, vote result, price change, affected population
- turning point: escalation, reversal, contradiction, new evidence, decision, judgment, negotiation result
- expert interpretation: cause, consequence, trend, risk, background, but only if it has a clear conclusion
- follow-up: investigation, rescue, settlement, policy execution, next action

Drop clips that are only empty shots, transitions, repeated background, program packaging, greetings, vague commentary, duplicated information, unclear audio, unusable visuals, or clips that cannot be understood and add no useful visual value.

Usage:
- "av": use for AI voiceover when the visual is useful but original audio is weak, noisy, incomplete, or not informative.
- "re": use for original-audio reassembly when the original speech/audio is clear, complete, and newsworthy.
- "both": use when both visuals and original audio are strong and the clip can support either workflow.
- "drop": use when the clip should not be used.

Independence:
- i=1 if the clip can be understood on its own.
- i=0 if the clip lacks enough information to understand the event by itself.

Context:
- c=1 if the clip needs another clip before or after it to be correctly understood.
- c=0 if it can be used without extra explanation, or if it is only visual B-roll for AI voiceover.

Story group:
Assign the same group id to clips about the same news event, policy, conflict, accident, person-driven storyline, location-driven event, or same development.

Rank:
Rank clips within the same story group.
- r=1: core backbone clip, essential fact, strongest statement, strongest scene, or key turning point
- r=2: strong supporting clip, public impact, data, expert conclusion, important reaction
- r=3: useful auxiliary clip, background, B-roll, secondary angle
- r=4 or higher: low-priority but still usable
```

# 十六、最终建议

你的 `candidate_refine` 最好不要追求复杂输出，而是让模型稳定做六件事：

```text
1. 有没有新闻功能 → k
2. 适合哪种生产模式 → u
3. 能不能单独看懂 → i
4. 是否必须依赖上下文 → c
5. 属于哪条新闻故事线 → g
6. 在同组里是不是主干 → r
```

这样后面的 `short_video_edit_plan` 和 `highlight_reassembly_plan` 才能更稳。

尤其对原声重组模式来说，最关键的是：

**优先选 `k=1, u=re/both, i=1, c=0或低上下文依赖, r=1/2` 的片段。**

对 AI 配音模式来说，最关键的是：

**可以接受 `i=0`，但画面必须有现场价值，且 `u=av/both`。**

这就是两个模式在 `candidate_refine` 阶段最应该分开的地方。
