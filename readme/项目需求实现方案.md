# 凤凰新闻视频智能拆条系统技术方案 v1

## 1. 项目定位

本系统面向 **凤凰卫视新闻素材、直播现场解说、记者连线、嘉宾评论、新闻专题、发布会、国际新闻报道** 等长视频内容。

目标是将一条新闻长视频自动分析，并输出一个或多个可发布的新闻短视频方案，后续可进一步自动粗剪、生成配音、字幕、标题、封面文案，并交由人工审核。

---

# 2. 核心目标

## 2.1 输入

系统输入为一条新闻长视频：

```text
input.mp4 / input.mov / input.m3u8
```

可选输入：

```text
栏目名称
新闻主题
目标发布平台
目标视频比例
是否需要配音
是否保留原声
已有字幕文件
```

---

## 2.2 输出

系统最终输出：

```text
1. 视频内容分析报告
2. 新闻时间轴 merged_timeline.json
3. 候选高光片段 candidate_clips.json
4. 短视频拆条方案 short_video_plan.json
5. 每条短视频剪辑脚本 editing_script.json
6. 解说文案 voiceover_script.json
7. OmniVoice 配音音频 voiceover.wav
8. 字幕文件 subtitles.srt
9. 自动剪辑 JSON cut_plan.json
10. 短视频粗剪成片 short_video_xxx.mp4
11. 风险审核报告 review_report.json
```

---

# 3. 系统设计原则

这个项目不能按普通短视频工具设计，因为新闻视频有更高的准确性要求。

系统必须遵循以下原则：

```text
1. 事实优先，不为了传播性牺牲准确性
2. 高光识别基于新闻价值，而不仅是情绪和冲突
3. 所有输出必须有时间码依据
4. 标题和解说不得编造视频里不存在的信息
5. 区分事实、表态、评论、推测
6. 区分现场画面、资料画面、主持人口播、嘉宾评论
7. 涉及时政、外交、战争、灾害、伤亡等内容必须标记风险
8. 自动生成结果必须进入人工审核
```

# 4. 整体技术架构

系统整体分为 9 层：

```text
A. 输入层
B. 视频预处理层
C. ASR 语音识别层
D. 多模态视频理解层
E. 时间轴融合层
F. 新闻编辑 Agent 层
G. 文案与配音层
H. 自动剪辑层
I. 审核与导出层
```

整体流程如下：

```text
新闻长视频
↓
视频预处理
↓
FunASR 转写
↓
Qwen / 豆包多模态视频理解
↓
ASR + 画面 + 时间码融合
↓
新闻理解 Agent
↓
高光识别 Agent
↓
短视频主编 Agent
↓
剪辑导演 Agent
↓
文案 Agent
↓
OmniVoice 配音
↓
FFmpeg / MoviePy 自动粗剪
↓
风险审核 Agent
↓
人工终审
↓
导出短视频
```

# 6. 模型职责分工

## 6.1 FunASR：语音转文字

FunASR 用于完成新闻视频中的语音识别。FunASR 官方介绍其能力包括 ASR、VAD、标点恢复、说话人分离等，适合构建从音频到结构化文本的处理链路。([GitHub][1])

在本系统中，FunASR 负责：

```text
1. 音频转文字
2. 输出时间码
3. 可选：VAD 分段
4. 可选：标点恢复
5. 可选：说话人分离
```

输出示例：

```json
{
  "segments": [
    {
      "start": 12.32,
      "end": 18.90,
      "speaker": "SPEAKER_01",
      "text": "现在我们来看国际局势的最新发展。"
    }
  ]
}
```

---

## 6.2 Qwen / 豆包多模态：视频画面理解

Qwen2.5-VL 官方介绍提到其具备长视频理解能力，并能定位视频中的相关事件片段；Hugging Face 模型页也提到其支持视觉定位和稳定 JSON 输出。([Qwen][2])

豆包 / Seed 方向也有视觉语言模型能力，ByteDance Seed 官方模型页介绍了 Seed1.5-VL / Seed1.6 等多模态模型。([字节跳动 Seed][3])

在本系统中，多模态模型负责：

```text
1. 识别画面类型
2. 判断是否为主持人口播、记者连线、现场画面、资料画面、嘉宾评论、发布会
3. 识别画面中的标题条、人名、地点、字幕、数据
4. 判断画面是否有新闻价值
5. 判断画面是否适合作为短视频开头
6. 判断是否有敏感画面
7. 检查画面和 ASR 文本是否匹配
```

输出示例：

```json
{
  "time_range": "00:03:00-00:03:30",
  "scene_type": "记者现场连线",
  "visual_summary": "记者站在户外进行直播连线，背景为城市街道。",
  "screen_text": ["凤凰卫视", "现场连线", "华盛顿"],
  "visible_people": ["记者"],
  "is_live_scene": true,
  "is_archive_footage": false,
  "visual_value_score": 8,
  "hook_score": 7,
  "risk_tags": []
}
```

---

## 6.3 文本大模型：新闻编辑判断

文本大模型负责“主编判断”，不是单纯总结。

它负责：

```text
1. 整体新闻理解
2. 找候选高光
3. 判断适合剪几条
4. 给每条短视频定选题
5. 生成剪辑脚本
6. 生成解说文案
7. 生成标题和封面文案
8. 做新闻风险审核
```

这一步可以用：

```text
Qwen 文本模型
豆包文本模型
GPT
Claude
DeepSeek
```

第一版建议优先使用和多模态模型同厂的文本模型，便于接口统一。

---

## 6.4 OmniVoice：文本转语音

OmniVoice 负责：

```text
解说文案 → 配音音频
```

注意：

```text
OmniVoice 不是 ASR。
FunASR 是语音转文字。
OmniVoice 是文字转语音。
```

系统链路是：

```text
视频音频 → FunASR → 文本
文本 → LLM → 解说稿
解说稿 → OmniVoice → 配音
```

---

## 6.5 OCR 是否需要单独接？

第一版不强制单独接 OCR。

建议：

```text
MVP：让 Qwen / 豆包多模态模型直接识别画面文字
生产版：如果发现字幕条、人名、地点、数据识别不稳定，再接 PaddleOCR / 云 OCR 做双路校验
```

为什么保留 OCR 预留口：

```text
新闻画面文字是事实来源，不是装饰信息。
标题条、地点、人名、身份、资料画面标识会影响新闻准确性。
多模态模型有时会漏掉小字、滚动字幕、繁体字、外文名。
```

所以设计上保留：

```text
visual_text_source = "multimodal" / "ocr" / "merged"
```

# 7. 完整处理流程

## 7.1 Step 1：视频输入

输入文件：

```text
input.mp4
```

生成任务 ID：

```text
task_id = newsclip_20260525_0001
```

创建目录：

```text
outputs/newsclip_20260525_0001/
```

---

## 7.2 Step 2：视频预处理

### 2.1 获取视频元信息

使用 FFprobe：

```bash
ffprobe -v quiet -print_format json -show_format -show_streams input.mp4
```

输出：

```json
{
  "duration": 1832.4,
  "width": 1920,
  "height": 1080,
  "fps": 25,
  "audio_codec": "aac",
  "video_codec": "h264"
}
```

---

### 2.2 提取音频

```bash
ffmpeg -i input.mp4 -ac 1 -ar 16000 outputs/audio.wav
```

输出：

```text
audio.wav
```

---

### 2.3 抽帧

MVP 建议每 5 秒抽一帧：

```bash
ffmpeg -i input.mp4 -vf fps=1/5 outputs/frames/frame_%06d.jpg
```

如果视频很长，可以改成每 10 秒一帧。

---

### 2.4 生成代理视频

给多模态模型分析时，建议压缩成低清代理视频：

```bash
ffmpeg -i input.mp4 -vf scale=1280:-1 -r 2 outputs/proxy_video.mp4
```

---

## 7.3 Step 3：FunASR 转写

输入：

```text
audio.wav
```

输出：

```text
asr_segments.json
```

建议输出结构：

```json
{
  "language": "zh",
  "segments": [
    {
      "id": 1,
      "start": 0.0,
      "end": 5.2,
      "speaker": "SPEAKER_00",
      "text": "各位观众晚上好，欢迎收看凤凰卫视资讯台。"
    }
  ],
  "full_text": "各位观众晚上好，欢迎收看凤凰卫视资讯台……"
}
```

MVP 先做到：

```text
带时间码文本
```

第二阶段再增强：

```text
说话人分离
专名修正
中英混合修正
繁简转换
```

---

## 7.4 Step 4：视频分段

为了让多模态模型稳定处理，不建议一次性把整条长视频全部丢给模型。

建议按 chunk 分段：

```text
每 60 秒一个 chunk
```

例如：

```json
{
  "chunks": [
    {
      "chunk_id": "CH001",
      "start": 0,
      "end": 60,
      "frames": ["frame_000001.jpg", "frame_000002.jpg"],
      "asr_text": "这一分钟的 ASR 文本"
    },
    {
      "chunk_id": "CH002",
      "start": 60,
      "end": 120,
      "frames": ["frame_000013.jpg", "frame_000014.jpg"],
      "asr_text": "第二分钟的 ASR 文本"
    }
  ]
}
```

---

## 7.5 Step 5：多模态模型分析

每个 chunk 调用 Qwen / 豆包多模态模型。

输入：

```json
{
  "chunk_id": "CH001",
  "time_range": "00:00:00-00:01:00",
  "frames": ["frame_000001.jpg", "frame_000002.jpg"],
  "asr_text": "各位观众晚上好……"
}
```

输出：

```json
{
  "chunk_id": "CH001",
  "time_range": "00:00:00-00:01:00",
  "scene_type": "主持人口播",
  "visual_summary": "主持人在演播室播报新闻，画面下方有新闻标题条。",
  "screen_text": ["凤凰卫视", "国际新闻"],
  "visible_people": ["主持人"],
  "is_live_scene": false,
  "is_archive_footage": false,
  "visual_value_score": 5,
  "hook_score": 4,
  "risk_tags": [],
  "notes": "该片段适合作为背景导语，但不适合作为强开头。"
}
```

---

## 7.6 Step 6：生成统一新闻时间轴

把 ASR 和多模态分析按时间码对齐。

输出：

```text
merged_timeline.json
```

结构：

```json
{
  "timeline": [
    {
      "start": "00:00:00",
      "end": "00:01:00",
      "asr_text": "各位观众晚上好……",
      "scene_type": "主持人口播",
      "visual_summary": "主持人在演播室播报新闻。",
      "screen_text": ["凤凰卫视", "国际新闻"],
      "speaker": "主持人",
      "visual_value_score": 5,
      "hook_score": 4,
      "risk_tags": []
    }
  ]
}
```

这是后面所有 Agent 的核心输入。

# 8. Agent 工作流设计

建议拆成 7 个 Agent，而不是一个 Prompt 全做完。

```text

```

## 8.3 短视频主编 Agent

### 目标

判断到底剪几条，而不是固定剪几条。

决策规则：

```text
0 条：素材价值不足或风险过高
1 条：单一核心新闻点
2-3 条：有现场、表态、解读等多个角度
4-6 条：长专题、直播回放、多议题素材
```

### 输出

```text
short_video_plan.json
```

### 输出格式

```json
{
  "recommended_video_count": 3,
  "overall_reason": "该视频包含现场进展、官方表态和专家解读三个相对独立的新闻角度。",
  "short_videos": [
    {
      "short_video_id": "SV001",
      "topic": "事件最新现场进展",
      "news_angle": "现场记者连线说明目前情况",
      "video_type": "现场型",
      "target_duration_seconds": 60,
      "source_clip_ids": ["C001"],
      "priority": "S",
      "reason": "画面现场感强，信息完整，适合作为第一条短视频。"
    }
  ],
  "discarded_clips": [
    {
      "clip_id": "C004",
      "reason": "信息重复，独立成片价值较低。"
    }
  ]
}
```


# 10. 自动剪辑实现方案

## 10.1 第一版粗剪逻辑

第一版不做复杂包装，只实现：

```text
1. 按时间码裁切原视频
2. 拼接多个片段
3. 转成 9:16 或保持原比例
4. 添加 OmniVoice 配音
5. 原声压低
6. 加字幕
7. 导出 mp4
```

FFmpeg 本身支持复杂滤镜、裁切、拼接、音频处理等能力；官方文档说明其 libavfilter 支持多输入多输出的过滤图，用于 crop、overlay、split 等处理。([FFmpeg][4])

---

## 10.2 裁切片段

示例：

```bash
ffmpeg -ss 00:02:13 -to 00:03:08 -i input.mp4 -c copy clip_c001.mp4
```

为了更精确，可以使用重新编码：

```bash
ffmpeg -i input.mp4 -ss 00:02:13 -to 00:03:08 -c:v libx264 -c:a aac clip_c001.mp4
```

---

## 10.3 拼接片段

生成 concat 列表：

```text
file 'clip_001.mp4'
file 'clip_002.mp4'
file 'clip_003.mp4'
```

执行：

```bash
ffmpeg -f concat -safe 0 -i concat_list.txt -c copy merged.mp4
```

如果片段尺寸、帧率、编码不一致，建议统一转码后再拼接。FFmpeg concat 文档也提示 concat filter 对输入的尺寸和帧率一致性有要求。([FFmpeg Trac][5])

---

## 10.4 转 9:16

新闻视频多数是 16:9，短视频平台需要 9:16。

MVP 三种模式：

```text
1. center：居中裁切
2. fit_blur：原画面等比缩放 + 背景模糊
3. speaker_focus：人物居中裁切，后续可用人脸/主体检测增强
```

第一版建议用：

```text
fit_blur
```

原因是新闻画面经常有标题条、字幕、多人画面，直接居中裁切容易裁掉关键信息。

FFmpeg 示例：

```bash
ffmpeg -i merged.mp4 -vf "scale=1080:-1,pad=1080:1920:(ow-iw)/2:(oh-ih)/2" output_9x16.mp4
```

更美观的背景模糊版后续再做。

---

## 10.5 添加配音并压低原声

逻辑：

```text
原视频音量降低到 20%-30%
OmniVoice 配音作为主声道
```

示例：

```bash
ffmpeg -i video.mp4 -i voiceover.wav \
-filter_complex "[0:a]volume=0.25[a0];[1:a]volume=1.0[a1];[a0][a1]amix=inputs=2:duration=first[a]" \
-map 0:v -map "[a]" -c:v copy -c:a aac output.mp4
```

---

## 10.6 加字幕

先生成 SRT：

```srt
1
00:00:00,000 --> 00:00:03,000
现场出现最新进展

2
00:00:03,000 --> 00:00:08,000
记者在现场介绍，目前相关区域仍在管控中
```

烧录字幕：

```bash
ffmpeg -i output.mp4 -vf subtitles=subtitle.srt final.mp4
```

# 14. 主流程伪代码

```python
def run_pipeline(input_video: str, config: dict):
    task = create_task(input_video)

    # 1. 视频预处理
    metadata = probe_video(input_video)
    audio_path = extract_audio(input_video)
    frames = extract_frames(input_video, interval_seconds=5)
    proxy_video = create_proxy_video(input_video)

    # 2. ASR
    asr_result = run_funasr(audio_path)

    # 3. 分 chunk
    chunks = build_chunks(
        duration=metadata["duration"],
        asr_segments=asr_result["segments"],
        frames=frames,
        chunk_seconds=60
    )

    # 4. 多模态理解
    visual_results = []
    for chunk in chunks:
        visual_result = run_multimodal_model(chunk)
        visual_results.append(visual_result)

    # 5. 时间轴融合
    merged_timeline = build_merged_timeline(
        asr_segments=asr_result["segments"],
        visual_segments=visual_results
    )

    # 6. 新闻理解
    video_analysis = run_agent(
        agent_name="video_understanding",
        input_data=merged_timeline
    )

    # 7. 高光识别
    candidate_clips = run_agent(
        agent_name="highlight_detection",
        input_data={
            "timeline": merged_timeline,
            "video_analysis": video_analysis
        }
    )

    # 8. 短视频规划
    short_video_plan = run_agent(
        agent_name="short_video_planner",
        input_data={
            "candidate_clips": candidate_clips,
            "video_analysis": video_analysis
        }
    )

    # 9. 剪辑脚本
    editing_script = run_agent(
        agent_name="editing_director",
        input_data={
            "short_video_plan": short_video_plan,
            "timeline": merged_timeline,
            "candidate_clips": candidate_clips
        }
    )

    # 10. 解说文案
    voiceover_script = run_agent(
        agent_name="voiceover_writer",
        input_data=editing_script
    )

    # 11. 风险审核
    review_report = run_agent(
        agent_name="risk_review",
        input_data={
            "editing_script": editing_script,
            "voiceover_script": voiceover_script,
            "video_analysis": video_analysis
        }
    )

    # 12. TTS
    voiceover_files = []
    for script in voiceover_script["scripts"]:
        wav = run_omnivoice(script)
        voiceover_files.append(wav)

    # 13. 自动剪辑
    cut_plan = build_cut_plan(
        input_video=input_video,
        editing_script=editing_script,
        voiceover_files=voiceover_files
    )

    draft_videos = render_draft_videos(cut_plan)

    return {
        "video_analysis": video_analysis,
        "candidate_clips": candidate_clips,
        "short_video_plan": short_video_plan,
        "editing_script": editing_script,
        "voiceover_script": voiceover_script,
        "review_report": review_report,
        "draft_videos": draft_videos
    }
```

# 16. 质量控制设计

## 16.1 ASR 质量控制

常见问题：

```text
人名识别错
地名识别错
机构名识别错
英文名识别错
多说话人混淆
直播现场噪音影响识别
```

解决方案：

```text
1. 加专名词表
2. 后处理纠错
3. 用画面标题条辅助校正
4. 关键片段人工确认
5. 必要时双 ASR 模型交叉验证
```

---

## 16.2 多模态质量控制

常见问题：

```text
小字识别不准
资料画面误判为现场画面
人物身份误判
画面地点误判
视觉信息和 ASR 不一致
```

解决方案：

```text
1. 要求模型输出 confidence
2. 对人名、地点、机构标注 uncertain
3. 保留 OCR 备用接口
4. 画面文字和 ASR 相互校验
5. 高风险片段必须人工审核
```

---

## 16.3 高光识别质量控制

常见问题：

```text
只选冲突性强但新闻事实不完整的片段
忽略背景
重复剪同一信息点
为了凑数量强行拆条
```

解决方案：

```text
1. 每条短视频必须有独立新闻主题
2. 每条必须有事实完整性评分
3. 低独立成片性片段必须补上下文
4. 风险过高片段不进入自动剪辑
```

---

## 16.4 文案质量控制

禁止：

```text
震惊体
煽动性标题
未经证实的判断
把嘉宾观点写成事实
把推测写成结论
```

推荐表达：

```text
据现场画面显示
现场记者介绍
目前信息显示
有分析认为
相关方面尚未进一步说明
后续情况仍有待观察
```

# 17. 新闻风险规则

系统需要内置风险规则。

## 17.1 高风险内容

```text
政治敏感
外交冲突
战争军事
灾害伤亡
血腥暴力
未成年人
抗议示威
突发公共安全事件
未经证实消息
```

## 17.2 高风险剪辑行为

```text
断章取义
改变原意
标题夸大
画面和解说不匹配
把资料画面说成现场画面
删除关键限定语
只保留情绪，不保留事实
```

## 17.3 审核输出

```json
{
  "risk_level": "high",
  "can_publish": false,
  "required_human_review": true,
  "reason": "该片段涉及外交表态，当前剪辑缺少前文提问背景，存在断章取义风险。"
}
```

# 21. 最终一句话总结

这套系统应该设计成：

```text
FunASR 负责听懂新闻；
Qwen / 豆包多模态负责看懂画面；
新闻编辑 Agent 负责判断高光和拆条；
OmniVoice 负责新闻解说配音；
FFmpeg / MoviePy 负责自动粗剪；
风险审核 Agent + 人工审核负责保证新闻准确性。
```

第一版重点不是把视频剪得多花，而是先做到：

```text
找点准
时间码准
文案稳
新闻风险可控
输出结构化
后续可自动剪辑
```
