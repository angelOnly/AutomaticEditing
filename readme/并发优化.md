## 一、当前代码现状

项目启动链路很清晰：

`python run_web.py` → `uvicorn.run("web_app:app")` → 前端调用 `/api/run` → `web_app.py` 用 `subprocess.Popen` 启动 `run_pipeline.py` → `run_pipeline.py` 调 `newsclip_agent.pipeline.main()`。`run_web.py` 会从 7860 开始自动找可用端口，保证仍然可以用 `python run_web.py` 启动。

`web_app.py` 当前所有运行任务存在内存变量 `JOBS` 里，服务重启后就丢；`/api/run` 每次创建一个 `job_id`，然后直接 `subprocess.Popen` 拉起一个新的 Python 子进程跑完整流水线。  

`pipeline.py` 内部是串行步骤执行，只有 `vision` 这一步对 chunk 做了线程池并发；当前默认 `vision_max_workers=3`，`vision_max_frames_per_chunk=6`，配置来自 `config.toml`。  

高光重组模式已经有独立步骤链：`metadata -> audio_extract -> frame_extract -> chunk_build -> asr -> vision -> timeline -> video_understanding -> highlight_detection -> highlight_reassembly_plan -> reassembly_cut_plan -> reassembly_render`。AI 配音模式是另一条步骤链。

前端当前有一个浏览器级别的 `state.activeJob` 锁。只要当前浏览器发现有任务在跑，就禁止再点“开始分析”或“重跑”。但这个锁只在当前浏览器有效，不能防止另一个人、另一个浏览器、或刷新后重复提交。

# 需求 2：字幕背景加宽、文字加粗、更好读

## 当前问题

当前字幕不是用单独的背景盒，而是用 FFmpeg `subtitles=...:force_style=...` 的 ASS 样式。`pipeline.py` 的 `_subtitle_force_style()` 当前只设置了字体大小、主色、描边色、`BorderStyle=1`、`Outline`、`Shadow`、`Blur`、`Alignment`、`MarginV`。

现在 `config.toml` 里字幕样式是：

```toml
font_size_16_9 = 24
font_size_9_16 = 20
outline = 3
shadow = 0
primary_colour = "&H00000000"
outline_colour = "&H00FFFFFF"
```



这套样式的问题是：

1. `BorderStyle=1` 是描边，不是字幕背景框。
2. 字幕没有 `Bold=1`。
3. 背景宽度无法通过 `BorderStyle=1` 变宽。
4. 黑字白描边在新闻视频复杂背景下不一定稳定，尤其画面亮的时候可读性差。

## 推荐方案

把字幕改成“半透明背景框 + 白色加粗字体”。ASS 样式里应该使用：

```text
BorderStyle=3
BackColour=&H80000000
PrimaryColour=&H00FFFFFF
Bold=1
Outline=0 或 1
Shadow=0
```

其中：

* `BorderStyle=3`：字幕后面有 box 背景。
* `BackColour=&H80000000`：半透明黑色背景。
* `Bold=1`：文字加粗。
* `MarginV`：控制离底部距离。
* `Spacing=0`：中文一般不用加字距。
* `FontName=Microsoft YaHei` 或 `Arial`：Windows 环境建议微软雅黑。

## 修改文件

```text
config.toml
newsclip_agent/pipeline.py
```

## config.toml 修改建议

把 `[subtitle]` 改成：

```toml
[subtitle]
mode = "sentence"
max_chars_per_line_16_9 = 24
max_chars_per_line_9_16 = 16
max_lines = 1
min_cue_seconds = 1.0
max_cue_seconds = 4.0
prefer_clause_split = true

font_name = "Microsoft YaHei"
font_size_16_9 = 30
font_size_9_16 = 28
bold = 1

margin_v_16_9 = 52
margin_v_9_16 = 150

primary_colour = "&H00FFFFFF"
outline_colour = "&H00000000"
back_colour = "&H80000000"

border_style = 3
outline = 1
shadow = 0
blur = 0
```

说明：

* 16:9 字号从 24 提到 30。
* 9:16 字号从 20 提到 28。
* 一行字数略增加，背景框会更宽。
* `BorderStyle=3` 后背景框宽度主要由字幕文本长度决定，所以 `max_chars_per_line_16_9` 可以从 22 提到 24，`9_16` 从 14 提到 16。
* 若你觉得背景还是窄，继续把 `max_chars_per_line_16_9` 调到 26。

## 可选增强：让背景更宽一点

ASS 的背景框默认只包住文字，没办法像 CSS 那样直接设置 padding。如果想让背景框更宽，可以在生成 SRT 时给字幕文本左右加全角空格，例如：

```python
def _pad_subtitle_text(self, text: str) -> str:
    cfg = self._subtitle_config()
    pad = int(cfg.get("box_padding_chars", 1))
    if pad <= 0:
        return text
    return "　" * pad + text + "　" * pad
```

然后在 `_subtitle_chunks_to_srt_blocks()` 这里：

```python
blocks.append(f"{index}\n{srt_time(cursor)} --> {srt_time(cue_end)}\n{chunk}\n")
```

改成：

```python
chunk_text = self._pad_subtitle_text(chunk)
blocks.append(f"{index}\n{srt_time(cursor)} --> {srt_time(cue_end)}\n{chunk_text}\n")
```

再在 `config.toml` 加：

```toml
box_padding_chars = 1
```

这个方案简单稳定，缺点是字幕行左右会多一点空白，但视觉效果正是你要的“背景加宽”。

# 需求 3：多人同时使用、并发优化、任务隔离又共享

## 当前问题原因

### 1. 前端只支持“当前浏览器一个任务”

`runSelected()` 里只要 `state.activeJob` 存在，就直接弹：

```js
alert("当前已有任务在运行，请等待完成后再启动新的运行。");
return;
```



这导致同一个浏览器不能同时提交多个任务。但另一个浏览器不受这个限制，所以它不是一个真正的后端并发控制。

### 2. 后端没有真正的任务队列和资源调度

`web_app.py` 的 `/api/run` 直接 `Popen`，没有判断当前 GPU 是否空闲、ASR 是否正在跑、TTS 是否正在跑、是否是重复任务。

### 3. 每个任务是独立 Python 子进程，模型无法共享

`pipeline.py` 里 `_get_asr_engine()` 会在当前进程内懒加载 FunASR。

`tts_omnivoice.py` 里有 `_MODEL_CACHE`，但这个缓存也是“进程内缓存”。如果 Web 同时拉起多个 `run_pipeline.py` 子进程，每个子进程都会各自加载 OmniVoice/FunASR，3090 24G 很容易被重复模型占满。 

### 4. 现在任务 ID 用时间戳，天然容易重复提交

`_make_task_id()` 当前逻辑是：

```python
return f"{prefix}_{_mode_slug(production_mode)}_{datetime.now().strftime('%Y%m%d_%H%M%S')}"
```



同一个视频，多个人重复点，会创建不同 task_id。系统无法知道“这是同一个素材、同一套参数、同一模式”。

### 5. 任务共享已经有基础，但不完整

`/api/tasks` 会读取 `outputs` 目录下所有任务，所以 A 提交的任务，B 在同一个 Web 服务里确实能看到。

但问题是：

* 没有提交者概念。
* 没有任务指纹。
* 没有复用同源任务。
* 没有“同任务正在运行，不重复提交”的锁。
* `JOBS` 在内存里，服务重启后运行状态丢失。

---

## 推荐总体架构：不要先做登录，先做“共享任务池 + 指纹去重 + 后端队列”

你这个场景我不建议第一版就做登录。因为你的真实诉求不是权限隔离，而是：

1. 多人能同时打开工作台。
2. A 提交的任务，B 能看到。
3. 同一个视频同一参数，不重复跑。
4. 不同视频可以排队或并发跑。
5. GPU 资源不要被多个子进程打爆。
6. 每个人的浏览器只关注自己当前选中的任务，但任务池是共享的。

所以最佳第一版是：

```text
无登录
共享任务池
任务指纹去重
后端任务队列
同任务互斥锁
全局资源信号量
前端允许看到所有任务与运行状态
```

后续如果需要权限，再加一个轻量昵称或 token，不要一开始就上完整登录系统。

## 1. 增加任务指纹 task_fingerprint

### 指纹应该包含什么

同一个任务的定义应该包括：

```text
source_video_hash
production_mode
aspect_ratio
chunk_seconds
frame_interval
target_duration_seconds
reassembly_target_seconds
reassembly_max_clip_count
reassembly_sort_mode
audio_policy
```

不要只用文件名。两个不同视频可能同名；同一个视频改了参数，也应该是新任务。

### 视频 hash 怎么取

不用每次读完整视频做 sha256，几十分钟视频会慢。第一版可以用：

```text
文件绝对路径 + 文件大小 + 文件mtime
```

后续再补充 `quick_sha256`，只读前 16MB + 后 16MB。

### 在 web_app.py 增加函数

```python
import hashlib

def _video_fingerprint(path: Path) -> dict[str, Any]:
    stat = path.stat()
    return {
        "path": str(path.resolve()),
        "size": stat.st_size,
        "mtime": round(stat.st_mtime, 3),
    }

def _run_fingerprint(req: RunRequest, input_path: Path | None) -> str:
    payload = {
        "video": _video_fingerprint(input_path) if input_path else None,
        "production_mode": req.production_mode,
        "aspect_ratio": req.aspect_ratio,
        "chunk_seconds": req.chunk_seconds,
        "frame_interval": req.frame_interval,
        "target_duration_seconds": req.target_duration_seconds,
        "audio_policy": req.audio_policy,
        "allow_original_audio_evidence": req.allow_original_audio_evidence,
        "reassembly_output_mode": req.reassembly_output_mode,
        "reassembly_sort_mode": req.reassembly_sort_mode,
        "reassembly_target_seconds": req.reassembly_target_seconds,
        "reassembly_max_clip_count": req.reassembly_max_clip_count,
    }
    raw = json.dumps(payload, ensure_ascii=False, sort_keys=True)
    return hashlib.sha256(raw.encode("utf-8")).hexdigest()[:16]
```

### 任务 ID 改造

现在 `_make_task_id()` 用时间戳。建议改成：

```python
def _make_task_id_from_fingerprint(input_video: str | None, production_mode: str, fingerprint: str) -> str:
    prefix = "task"
    if input_video:
        name = Path(input_video).stem
        safe = "".join(ch if ch.isalnum() else "_" for ch in name).strip("_")
        prefix = safe[:24] or "task"
    return f"{prefix}_{_mode_slug(production_mode)}_{fingerprint}"
```

这样同一个视频同参数永远落同一个 task_id。

```python
def _find_running_job_by_task_id(task_id: str) -> dict[str, Any] | None:
    for job_id, job in JOBS.items():
        public = _refresh_job(job_id)
        if public.get("task_id") == task_id and public.get("status") == "running":
            return job
    return None

def _is_task_already_completed(manifest: dict[str, Any], production_mode: str) -> bool:
    if not manifest:
        return False
    steps = manifest.get("steps", {})
    final_step = "reassembly_render" if production_mode == "highlight_reassembly" else "render"
    return steps.get(final_step, {}).get("status") in {"success", "partial_success"}
```

## 4. 更好的方式：队列，不拒绝

建议新增状态：

```text
queued
running
success
failed
```

`/api/run` 不直接 `Popen`，而是把任务写入队列。后台调度器根据并发上限启动。

### web_app.py 增加全局队列

```python
import threading
import queue

JOB_QUEUE: queue.Queue[str] = queue.Queue()
JOB_LOCK = threading.Lock()
SCHEDULER_STARTED = False
```

`JOBS[job_id]` 里先写：

```python
JOBS[job_id] = {
    "job_id": job_id,
    "task_id": task_id,
    "cmd": cmd,
    "log": relpath(log_path, ROOT),
    "log_path": str(log_path),
    "created_at": datetime.now().isoformat(timespec="seconds"),
    "started_at": "",
    "status": "queued",
    "returncode": None,
}
JOB_QUEUE.put(job_id)
```

启动调度线程：

```python
@app.on_event("startup")
def start_scheduler() -> None:
    global SCHEDULER_STARTED
    if SCHEDULER_STARTED:
        return
    SCHEDULER_STARTED = True
    thread = threading.Thread(target=_job_scheduler_loop, daemon=True)
    thread.start()
```

调度循环：

```python
def _job_scheduler_loop() -> None:
    while True:
        job_id = JOB_QUEUE.get()
        try:
            _wait_until_slot_available()
            _start_job_process(job_id)
        except Exception as exc:
            job = JOBS.get(job_id)
            if job:
                job["status"] = "failed"
                job["user_message"] = str(exc)
                job["finished_at"] = datetime.now().isoformat(timespec="seconds")
        finally:
            JOB_QUEUE.task_done()
```

等待并发槽：

```python
def _wait_until_slot_available() -> None:
    server_cfg = PROJECT_CONFIG.raw.get("server", {})
    max_running = int(server_cfg.get("max_running_jobs", 2))
    while True:
        if _running_job_count() < max_running:
            return
        time.sleep(1.0)
```

把现在 `/api/run` 中的 `subprocess.Popen` 移到：

```python
def _start_job_process(job_id: str) -> None:
    job = JOBS[job_id]
    log_path = Path(job["log_path"])
    log_file = log_path.open("a", encoding="utf-8", errors="replace")
    cmd = job["cmd"]

    env = os.environ.copy()
    env["PYTHONIOENCODING"] = "utf-8"
    env["PYTHONUTF8"] = "1"
    env["PYTHONUNBUFFERED"] = "1"

    process = subprocess.Popen(
        cmd,
        cwd=str(ROOT),
        stdout=log_file,
        stderr=subprocess.STDOUT,
        text=True,
        encoding="utf-8",
        errors="replace",
        env=env,
        creationflags=subprocess.CREATE_NO_WINDOW if os.name == "nt" else 0,
    )

    job.update({
        "pid": process.pid,
        "process": process,
        "log_file": log_file,
        "started_at": datetime.now().isoformat(timespec="seconds"),
        "status": "running",
    })
```

这个阶段仍然是子进程，但至少不会无限启动。

# 阶段二：真正适合 3090 的并发方案

阶段一虽然能防止乱跑，但每个任务还是子进程，模型不能共享。真正优化应该改成：

```text
Web 进程内任务队列
PipelineRunner 后台线程执行
FunASR 常驻加载
OmniVoice 常驻加载
GPU 模型加锁或信号量
LLM API 并发放开
FFmpeg/IO 控制并发
```

## 为什么这样更适合你的机器

你的瓶颈不是大模型 API，而是本地 GPU 模型：

* FunASR：本地 GPU。
* OmniVoice：本地 GPU。
* FFmpeg：CPU/IO。
* 视觉大模型：API，不占本地 GPU。

所以应该把本地模型变成“共享服务”，避免每个任务子进程重复加载。

## 1. 新增 runtime_locks.py

```python
from __future__ import annotations

import threading
from contextlib import contextmanager

# 3090 24G 第一版建议 ASR/TTS 共用一个 GPU 重活锁
GPU_MODEL_LOCK = threading.RLock()

# LLM 是 API，可并发高一点
VISION_LLM_SEMAPHORE = threading.Semaphore(8)
TEXT_LLM_SEMAPHORE = threading.Semaphore(4)

# FFmpeg 粗剪/渲染吃 CPU/IO，限制一下
FFMPEG_SEMAPHORE = threading.Semaphore(2)

@contextmanager
def gpu_model_section():
    with GPU_MODEL_LOCK:
        yield

@contextmanager
def vision_llm_section():
    with VISION_LLM_SEMAPHORE:
        yield

@contextmanager
def text_llm_section():
    with TEXT_LLM_SEMAPHORE:
        yield

@contextmanager
def ffmpeg_section():
    with FFMPEG_SEMAPHORE:
        yield
```

# 是否需要登录？

## 我的建议：第一版不需要登录

你的需求是“隔离又共享”，这不是典型账号权限问题，而是任务协作问题。

更适合的第一版方案是：

```text
不登录
所有任务共享可见
每个任务有 task_id
每个任务有 source_video + fingerprint
每个 job 有 client_id
前端用 localStorage 生成 client_id
同任务去重
任务详情所有人可看
删除操作只保留右键 + confirm
```

## 轻量 client_id 实现

前端加：

```js
function getClientId() {
  let id = localStorage.getItem("phoenix_client_id");
  if (!id) {
    id = crypto.randomUUID();
    localStorage.setItem("phoenix_client_id", id);
  }
  return id;
}
```

`baseRunRequest()` 里加：

```js
client_id: getClientId()
```

后端 `RunRequest` 加：

```python
client_id: str | None = None
```

任务里记录：

```python
"submitted_by": req.client_id or "anonymous"
```

这样不是登录，但可以知道哪个浏览器提交的任务。

## 什么时候才需要登录？

只有当你需要这些功能时才上登录：

```text
不同用户不能删除别人的任务
不同用户只能看自己的私有素材
需要审计谁提交了什么
需要公网部署给外部多人使用
```

如果只是团队内网/本机局域网工作台，不需要登录。

# 结论

你的项目现在不是“完全不能并发”，而是“没有后端级任务调度”。当前只有 vision chunk 内部并发，Web 层是直接开子进程，前端是单浏览器锁，后端没有去重、没有队列、没有 GPU 资源控制。

我建议不要先做登录。第一版应该做：

```text
右键删除
字幕 ASS 样式增强
任务指纹去重
共享任务池
后端队列
GPU 重活串行/限流
LLM API 并发放开
```

这样既能保持：

```bash
python run_web.py
```

也能解决你说的：

```text
A 提交了任务，B 能看到；
B 重复提交，不重复跑；
多人不同任务，可以排队或有限并发；
模型跑在 3090 上，不被多个子进程重复加载打爆。
```
